# UI 간격·팝업·버튼 공통 규칙

기준일: 2026-11-11. 사용자 피드백으로 확정한 최신 규칙이다. 과거 문서의 ‘보조 버튼 연두색 채움’ 및 ‘결과 팝업 상단 고정’ 규칙을 대체한다. 화면 디자인의 기본은 PDF, 아래 항목은 이후 확정한 공통 동작이다.

## 1. 구현 기준과 의존성

- 토큰: `apps/miniapp/src/tokens.css`, 디자인 자료: `design/tokens.json`.
- 공통 Button/Modal: `apps/miniapp/src/ui/primitives/index.tsx`.
- 공통 간격·위치·색상 적용: `apps/miniapp/src/layout.css`. 기본 CSS보다 뒤에서 불러온다.
- 버튼은 공통 Button을 사용하고, 팝업은 공통 Modal을 사용한다. 화면별로 별도 색상이나 위치를 덧붙이지 않는다.
- 글꼴은 PDF 원본에서 번들한 AIMI UX Regular/Bold를 사용한다. 입력창·버튼·팝업도 같은 글꼴을 따른다.

## 2. 컴포넌트 간격

간격은 글자 기준선이 아닌 요소의 실제 박스 사이를 기준으로 한다. 숫자를 화면마다 임의로 추가하지 않고 토큰을 사용한다.

|용도|토큰|기본값|
|---|---|---|
|아이콘·작은 장식 간격|space-1|4px|
|같은 그룹의 요소·버튼 간격|space-peer|8px|
|설명에서 목록으로 이어지는 간격|space-copy-list|12px|
|일반 콘텐츠 사이·카드 내부 패딩|space-content / card-padding|16px|
|섹션·본문에서 주요 버튼으로 넘어가는 간격|space-section|24px|
|페이지 좌우 여백|page-margin|24px|

- 페이지 첫 콘텐츠 위 여백은 중복 적용하지 않는다. 첫 자식 여백 규칙에서 dialog는 반드시 제외한다.
- 제목 다음 설명은 8px, 일반 콘텐츠 사이 기본16px, 새로운 섹션은24px로 구분한다.
- 페이지에서 세로로 이어지는 공통 버튼의 간격은8px. 별도 기능 묶음은 해당 컨테이너의 간격 토큰을 따른다.
- 텍스트는 고정 높이에 잘라 넣지 않는다. 긴 이름·수량·한글/영문 혼합·줄바꿈을 허용하고 min-width:0으로 넘침을 막는다.
- 좁은 화면에서도 버튼·이미지·문구가 서로 눌려 겹치지 않도록 한다. 필요한 경우 내용 높이를 늘린다.

## 3. 팝업 위치·크기

- 일반 팝업: fixed, inset:0, margin:auto로 뷰포트 중앙. 호출 위치나 화면 첫 자식 여부가 좌표를 바꾸면 안 된다.
- 기본 너비: 화면 너비에서48px를 뺀 값과432px 중 작은 값. 패딩 포함 border-box, 최대 화면 너비에서32px를 뺀 값 이내.
- 최대 높이: 100dvh - 48px. 긴 내용은 팝업 안에서 스크롤한다.
- 하단 시트만 예외: 화면 하단에 고정, 최대480px 너비/78dvh 높이, 하단 안전 영역 포함.
- 팝업 내부 패딩16px, 제목과 본문16px, 본문 내 일반 요소8px, 본문과 하단 버튼24px.
- 상품 미리보기 다음 여백16px, 가격 표의 행 간격16px, 가격 표 다음 설명12px.
- 바깥 클릭·닫기·뒤로가기는 팝업 취소 동작을 따른다. 필수 보상 확인처럼 dismissible=false인 경우는 임의로 닫지 않는다.
- 구매·요청 처리 중에는 중복 제출과 닫기를 제한한다. 닫기/취소만으로 예산·EP를 차감하지 않는다.

## 4. 버튼 색상·크기·순서

|역할|표현|
|---|---|
|주요 실행|brand #527A41 배경, 흰 글자, 모서리16px|
|보조 실행·취소|배경·테두리·그림자 없는 텍스트, brandText #274E2F|
|단순 이동·펼침|배경 없는 텍스트 링크|
|비활성 공통 버튼|기본 표현에 opacity 0.5, 실행 불가|

- 기본 클릭 영역 높이56px. 보조 행동도 클릭 영역을 유지하되 상자 배경은 표시하지 않는다.
- 팝업에서 긴 문구는 줄바꿈하고 높이를 확장한다. 같은 행의 두 버튼은 같은 너비·높이로 맞춘다.
- 세로 묶음: 진한 주요 실행이 맨 위, 보조 텍스트가 아래. DOM/키보드 탐색 순서도 같은 순서다.
- 팝업 버튼1개: 전체 너비. 버튼2개: 동일 너비 가로2열, 간격8px. 왼쪽 실행, 오른쪽 취소.
- 추가 보조 링크가 있으면 두 버튼 아래 전체 너비로 표시한다.
- 선택 탭·힌트 상품·상점 상품 카드·수량 증감은 CTA와 구별한다. 선택/상품 표면까지 모두 투명하게 바꾸지 않는다.
- 임의로 만든 원시 button으로 공통 CTA 스타일을 다시 구현하지 않는다.

## 5. 소셜 삭제 메뉴

- 점3개와 삭제 영역은 처음부터 고정된 좌표를 사용한다. 열림 여부로 점3개나 친구 본문을 움직이지 않는다.
- 삭제는 점3개 바로 오른쪽, 간격0의 텍스트 메뉴로 표시한다. 바깥 중첩 상자·패딩·불필요한 공백을 만들지 않는다.
- 삭제 클릭은 즉시 삭제가 아니라 확인 팝업을 연다. 왼쪽 삭제/오른쪽 취소.
- 바깥 클릭·Escape·뒤로가기는 메뉴를 닫는다. 친구 카드 방문과 메뉴 동작은 분리한다.

## 6. 상점의 보유 캐릭터

- 이미 보유한 캐릭터: ‘보유 중이에요’ 제목, 캐릭터 미리보기·이름, ‘정원 편집으로’ 단일 실행 버튼.
- 가격·합계·구매 후 EP·EP 부족 안내·구매 문구·구매 API 호출은 표시/실행하지 않는다.
- 닫기 아이콘으로 취소할 수 있다. 정원 편집 이동 자체로 캐릭터를 변경하거나 구매하지 않는다.
- 미보유 캐릭터와 수량 구매가 가능한 정원 아이템은 기존 구매 확인을 사용한다.

## 7. 변경 시 확인

공통 토큰/컴포넌트로 구현됐는지, 긴 문구와 좁은 화면에서 겹침이 없는지, 팝업 순서와 취소 동작이 일치하는지 확인한다. 타입 검사·필요한 빌드를 실행한다. 브라우저·실기기 검증을 하지 않은 경우 그 한계를 따로 기록하며 코드 검사만으로 시각 검증 완료라 부르지 않는다.

## 8. 키워드 선택과 미션 썸네일

- 키워드 선택은 목표 이미지를 전체 너비로 표시(최대 높이280px, 비율 유지)하고 Day 제목/목표 확대 링크를 반복 표시하지 않는다.
- 개수 힌트는 선택 안내 제목·설명 오른쪽에 같은 높이로 배치한다. 긴 안내는 왼쪽 영역에서 줄바꿈한다.
- 미션 썸네일은 crossing/dino/runner별 독립 SVG 배경을 사용하며 착용 캐릭터를 위에 표시한다. 저장 위치는 apps/miniapp/public/content/game-previews.

### 개수 힌트 카드 크기·색상 보정

개수 힌트는 연한 초록색(background-bottom), 진한 녹색 글자, 얇은 녹색 테두리로 표시한다. 높이44px/너비88px/아이콘16px로 줄이고, 선택 안내 제목·설명 묶음과 세로 중앙을 맞춘다. 안내가 줄바꿈되어도 카드 높이를 늘리지 않는다.

## 9. 브랜드 로고 정렬

로고 PNG 전체 캔버스 대신 실제 심볼이 있는 영역을 SVG viewBox로 표시한다(원본 PNG 보존). 홈 로고는72×34px 표시 영역, 헤더 제목의44px 높이 안에서 중앙 정렬하며 본문과 같은 왼쪽 여백을 사용한다. 공지·EP도 같은 행에서 중앙 정렬하고 간격12px, EP 숫자/단위 사이6px를 적용한다. 로딩/로그인은126×59px로 표시한다. 로고 파일 여백 때문에 화면별 임의의 음수 margin을 넣지 않는다.

## 10. 챌린지 첫 진입 안내와 보조 버튼 구현

- 키워드 선택의 첫 진입에는 목표 이미지에서 대상/개수/색상/배경/그림체 단어를 찾는 방법, 조합 확인/제출/재시도와 제출30/힌트15 예산 사용을 설명하는 팝업을 표시한다.
- 확인 또는 닫기는 날짜+콘텐츠 버전별 sessionStorage에 기록한다. 같은 세션/문제에서 반복 표시하지 않는다. 결과/해설 화면에는 띄우지 않는다.
- 이미지 아래에는 목표와 단서를 설명하는 짧은 문장을 항상 표시한다.
- 공통 Button의 weak는 이제 TDS weak 컴포넌트를 사용하지 않고 네이티브 button으로 렌더링한다. 동일 글꼴/56px 클릭 영역/비활성/aria-busy를 유지하며 배경/테두리/그림자/가상 요소 표면을 없앤다. 주요 실행만 TDS fill을 사용한다.

## 11. 챌린지 문장 강조

조합 확인의 조합 문장과 도전 결과의 이번 문장은 공통 SentenceCard를 사용한다. 연한 초록 weak 배경, 테두리/그림자 없음, 모서리16px, 내부 패딩16px, 제목-문장 간격8px. 제목14px/20px 진한 녹색 볼드, 문장16px/24px 일반 굵기. 문장 전체를 볼드로 만들지 않으며 키워드 판정·일치율은 상자 밖에 표시한다. 해설의 기존 원문 표기는 정답 프롬프트로 변경한다. 저장된 생성 원문 데이터는 변경하지 않는다.

## 12. 미션 이미지와 챌린지 종료

미션의 목표 이미지는 본문 전체 너비/왼쪽 선에 맞추고 실제 이미지 비율을 유지한다. 공통330:145 비율을 강제로 적용해 이미지 양쪽에 내부 여백이 생기지 않도록 mission-target-image에서 aspect-ratio:auto를 사용한다.

챌린지 성공/최종 실패 후에는 잔여 게임이 있어도 남은 게임 계속하기를 표시하지 않는다. 게임 직접 진입도 미션으로 돌려보낸다. 서버는 종료된 날의 새 게임 시작/활성 게임 재개/미정산 결과 지급을 거절하며 완료된 결과의 재조회는 기존 멱등성을 유지한다. 다음 날짜의 새 미션은 다시 플레이할 수 있다.

## 13. 소셜 친구 길게 누르기 (최신 규칙)

기존 점3개 메뉴 규칙을 폐기한다. 친구 카드를 짧게 누르면 정원 방문,550ms 길게 누르면 삭제 확인 팝업을 연다.10px 이상 이동/스크롤 pointercancel/카드 밖으로 이동/컴포넌트 제거 시 타이머를 해제한다. 길게 누른 뒤 발생하는 클릭으로 정원에 들어가지 않는다. 실제 삭제는 팝업의 왼쪽 삭제 버튼에서 실행하며 오른쪽은 취소다. 마우스 오른쪽 클릭/Shift+F10/Delete 키로도 확인 팝업을 열 수 있다. 받은 친구 요청은 길게 누르기에서 제외하고 짧게 누르는 수락 동작을 유지한다. 오른쪽 메뉴용 빈 영역은 제거한다.

## 14. 검수 후 정답 프롬프트·생성 원문·학습 설명

검수 콘텐츠 v3에서는 ‘정답 프롬프트’에 이미지에서 확인한 정답 조건으로 정리한 예시를 표시한다. 실제 요청 원문을 사후 변경한 것처럼 보이지 않도록 ‘실제 생성에 사용한 프롬프트’ 펼침에 원문과 작성 형식을 그대로 제공한다. 오늘의 작성 포인트2개와 모델 참고 팁1개를 별도 제목으로 구분한다. 모델 출처는 외부 링크 대신 출처명 텍스트로 표시한다. 근거 전체는 콘텐츠 sources.json/검수 문서에서 관리한다. 이전 도전의 저장된 reveal은 그대로 표시하고 이후 콘텐츠 버전으로 재해석하지 않는다.

## 15. 챌린지 이전 조합·해설 출처

- 조합 확인/결과는 공통 PreviousCombinations를 사용한다. ‘이전 조합 N회 보기’를 펼치면 회차별 결과가 화면 아래에 표시된다. 회차 제목은 한 번만 표시하고 빈 내역은 숨긴다. 이동/키워드 변경을 발생시키지 않는다.
- 화면은 챌린지 결과/차 챌린지로 통일한다. 횟수 설명은 시도로 표기하며 내부 API 필드는 유지한다.
- 모든 작성/모델 팁은 challenge-learning-tip으로 묶는다. 제목14/20px, 본문15/22px, 출처12/18px, 내부 간격space-peer(8px). 출처는 텍스트로 줄바꿈을 허용한다.
- 원인: puzzle-reveal의 직계 자식 간격만 정의된 상태에서 팁이 중첩 div로 추가됐다. 전역 p margin:0과 결합하여 내부 제목·본문·출처가 붙었다. 새 중첩 콘텐츠에는 내부 간격 계약을 명시한다.


## 7. 토스 상태바·내비게이션·안전 영역

- React 첫 렌더 전에 `lib/safe-area.ts`에서 SDK `SafeArea.get()`으로 상하좌우 값을 읽고 `SafeArea.subscribe()`로 변경을 반영한다. 화면별로 SDK를 다시 호출하거나 별도 보정값을 넣지 않는다.
- CSS의 `--safe-top/right/bottom/left`는 SDK 값과 CSS `env(safe-area-inset-*)` 중 큰 값을 사용한다. 두 값을 더해 중복 적용하지 않는다.
- 투명 토스 내비게이션을 쓰므로 시스템 상단 안전 영역 아래에 별도 48px 내비게이션 행을 확보한다. 본문, 홈 헤더, 테스트 안내는 그 아래에서 시작한다.
- 페이지와 게임 모두 공통 app-shell이 상단·좌우 영역을 담당한다. 게임 HUD·일시정지 버튼은 이미 보정된 게임 영역 기준으로 배치한다.
- 하단 탭·CTA·토스트는 같은 하단 안전 영역 변수를 사용한다. 키보드가 열리면 하단 탭을 숨긴다.
- 로딩·로그인은 app-shell 밖에 있으므로 같은 공통 변수를 직접 적용한다.
- 테스트 계정 안내는 헤더 아래 한 줄로 표시한다. 상세 호출 한도는 계정 관리에 표시한다.
- 게임 결과는 팝업이 아닌 페이지다. 공통 헤더의 ‘게임 결과’를 반복하는 제목을 추가하지 않는다.
- 이 규칙은 일반 페이지·고정 UI 대상이다. 팝업은 기존 공통 Modal 규칙을 유지한다.


## 8. iOS 입력 확대 예방

모든 input/textarea/select/contenteditable의 실제 계산 글꼴은 최소16px이다. 공통 CSS에서 우선 적용하고 개별 검색창·폼의 font:inherit로 축소하지 않는다. 버튼·링크 더블탭은 manipulation을 사용하며 게임 조작의 touch-action:none은 유지한다. 접근성을 위해 pinch 확대를 일괄 비활성화하지 않는다. 실제 iPhone 키보드 열기/닫기 후 스크롤·확대 복귀를 새 번들에서 확인한다.


## 9. 모바일 팝업 문구·즉시 반응

- 2버튼 팝업은 기존처럼 왼쪽 주요 실행/오른쪽 취소를 유지한다. 버튼은 한 줄의 짧은 동사로 표시하고 버튼 안 br/글자별 강제 줄바꿈을 금지한다. 가격·예산 비용·상품명은 본문에서 설명한다.
- 예: 선택하기/구매하기/저장하기/다시 확인/15예산 쓰기. 동적 캐릭터 이름이나 가격을 좁은 반폭 버튼에 반복하지 않는다.
- 버튼 문구13~16px, 제목16~18px 범위에서 반응형 적용. 금액은 한 묶음으로 유지한다. 긴 본문과 제목은 의미 단위 줄바꿈을 허용하며 잘라 숨기거나 말줄임하지 않는다.
- Modal은 useLayoutEffect에서 즉시 열고 dialog 자체에 preventScroll focus를 준다. 닫을 때도 이전 요소가 연결돼 있을 때만 preventScroll focus로 복원한다.
- 배경 실시간 blur 대신 반투명 녹색 scrim으로 합성 비용을 줄인다. 입력 안전 영역과 기존 패널 색/팝업 배치는 유지한다.
- 출석 팝업은 클릭 즉시 표시하되 처리 중/실패/확정 보상을 구분한다. 서버 승인 전 보상액이나 성공을 표시하지 않는다. 구매 완료도 서버 승인 후 열고 반환된 잔액만 표시한다. 후속 state 갱신은 뒤에서 한다.
- 로딩 중 공통 버튼은 실제 disabled 처리한다. 주요 버튼/카드의 active 피드백은 즉시 표시한다.


## 10. 스크롤 소유권과 네이티브 메뉴 보호(최신)

- 상단 안전 공간/제목은 app-shell에 고정하고 main.page만 세로 스크롤한다. window/document 전체를 스크롤하지 않는다. 각 main의 최소 높이를 화면 높이로 다시 더하지 않는다.
- 스크롤 저장/복원은 lib/page-scroll.ts가 활성 main의 scrollTop을 사용한다.
- 일반 팝업 inset은 상단 content-safe-top/좌우 safe/하단 safe를 사용한다. 이전 inset:0보다 이 규칙이 우선한다. 긴 팝업은 안전 영역 안에서 내부 스크롤한다.
- 짧은 화면을 맞추려고 글/그림/버튼을 잘라 숨기지 않는다. 미션/조합/정원 편집의 중복 여백·안내만 줄인다. 키워드/상점/긴 결과/상세 정보는 스크롤을 유지한다.
- 보상 알림은 금액+EP를 볼드로 표시한 강조 배경 상자다. 이전 ‘챌린지 보상은 텍스트만’ 정책을 사용자 최신 요구로 대체한다.
- 자세한 화면별 결과는 SCROLL_AND_SAFE_AREA_AUDIT_20261112.md를 따른다.
