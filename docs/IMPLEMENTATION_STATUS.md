## 최근 반영한 화면·사용성 변경

- 홈/시작 화면 로고 정리, 상태 조회 후 홈 우선 표시, 본문과 이미지 좌우 정렬.
- 개선·추천의 독립된 일일 남은 횟수 표시. 기본 각 5회, 실제 추천 분석 요청 때 추천 한도 사용.
- 보상을 받은 오늘의 팁 재확인 문구 분리.
- 해설은 정답 프롬프트 하나·번호형 작성 포인트·생성 모델 링크로 정리. 하이라이트 세로 두께 축소.
- 10일치 모델 팁에 실제 생성 회사/모델, 가이드명과 당일 적용 사례를 연결.
- 공식 상단 내비게이션과 본문 스크롤·안전 영역을 분리하고 키보드/너비 문제를 보완.

## 운영 구성과 산출물

- 프론트엔드: 앱인토스 `.ait`. 기존 웹 데모는 운영 경로가 아니다.
- API: https://aimi-online-api.onrender.com
- 데이터: Supabase PostgreSQL·Storage. 실제 기록은 서버 계정 기준으로 유지된다.
- 현재 로컬 전달 파일: `output/releases/AIMI_FINAL.ait`, 식별 정보는 `AIMI_FINAL.bundle.json`.
- 재빌드한 로컬 파일이 콘솔 버전을 자동 교체하지는 않는다. 실제 공개 버전과 로컬 산출물의 대응은 업데이트 때 기록한다.

## 배포 상태와 검증 기록의 구분

배포 완료를 모든 환경의 테스트 통과나 법률 검토 완료로 확장하지 않는다. 이전 점검의 미측정 성능, 실제 두 사용자 사이 소셜 시나리오 등은 별도 검증 기록이 있어야 통과로 표시한다. 현재 소셜은 푸시·실시간 구독 없이 목록 재조회로 변경 사항을 반영한다.

운영 후 점검은 [업데이트 점검](RELEASE_READINESS.md), 배포 변경은 [유지보수·배포](DEPLOYMENT.md)를 따른다. Render 인증서·환경변수 변경은 운영자 관리 범위다. 기록·지갑·기존 보상을 문서 정리나 테스트 목적으로 초기화하지 않는다.

## 기록 읽는 법

[운영 이력](RELEASE_HISTORY.md)에 출시 전 점검·웹 데모 종료를 요약했다. 날짜가 붙은 과거 감사·설계 문서는 당시 구현과 점검 범위를 설명하며 현재 출시 차단 목록이 아니다. 상세 변경 이력은 Git 이력을 참고한다.
