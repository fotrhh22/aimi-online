# 정원 자유 배치

## 최신 · 그림 경계와 수집함 (2026-11-09)

원본 SVG의 빈 여백을 배치 크기로 사용하지 않는다. 정원 전용 SVG는 tools/assets/prepare-garden.mjs가 원본 그림을 유지한 채 viewBox를 잘라 생성한다. 공통 규격 packages/contracts/src/garden.ts의 GARDEN_ITEM_GEOMETRY가 선택 테두리·장면 크기·서버 경계를 함께 결정한다. 정원 비율은327:300, 앵커는 하단 중앙이다.

|아이템|정원 폭 대비 크기|정원 전용 viewBox|
|---|---|---|
|울타리|34%|6 18 114 58|
|벤치|26%|8 36 104 51|
|화분|13%|29 10 63 84|
|꽃|8.5%|41 16 38 74|

기존4종 모두 원본 캔버스의 여백 영향을 받았다. 정원 렌더링에는 content/garden 변형을 사용하고 상품 썸네일 원본은 유지한다. 선택·배치 경계는 그림에 맞추고 터치 영역은 별도의 최소44px 영역으로 확보한다. 새 에셋도 동일 규격으로 검수·등록해야 한다. 서버 경계와 화면 경계에 다른 크기를 사용하지 않는다. 좌표 반올림 후에도 허용 경계를 벗어나지 않도록 안쪽으로 보정한다.

수집함은 폭96px·최소 높이116px의 가로 스크롤 카드이며 배치 후 잔여 수량을 표시한다. 카드 높이는 내용에 따라 늘어난다. 정원의 캐릭터/정원 상점 버튼은 높이76px다. 울타리를 오른쪽 아래/왼쪽 위 경계까지 실제 드래그하여 저장했으며 화분·꽃 추가와320px 가로 스크롤을 브라우저로 확인했다. API와 클라이언트를 함께 반영하며 새 SQL은 없다.

## 최신 추가 · 수량 구매와 여러 개 배치 (2026-11-09)

- 정원 상품은 수량1~99개를 선택해 재구매할 수 있다. 서버가 정수 수량·보유 상한99개/종류·총 EP·중복 요청을 transaction 안에서 검증한다. 캐릭터는 종류당1개만 구매한다.
- 기존 inventory:string[]의 각 항목을 구매한1개로 계산한다. 기존 단일 보유 데이터는1개로 유지한다. JSON 상태를 재사용하므로 새 SQL은 없다.
- placements에 instanceId를 추가하여 같은 itemId도 각각 선택·드래그·회수할 수 있다. 이전 배치는 호환 ID로 읽는다. 동일 instanceId 중복, 보유 수량 초과 배치, 전체12개 초과 배치는 서버에서 거절한다.
- 수집함 표시는 총 보유 수량에서 현재 편집 배치 개수를 뺀 값이다.2개 구매→×2,1개 배치→×1,2개 배치→×0/모두 배치 중,1개 회수→×1. 편집 취소는 저장된 배치 기준으로 돌아간다.
- 상품의 적용 범위/배치 상태 행을 삭제했다. 수량 조절·단가·합계·구매 후 EP를 표시한다. 수집함은 크림색 카드·연두색 테두리·수량 배지로 농장 수집 느낌을 적용한다. 새 외부 에셋은 사용하지 않는다.
- 별도 로컬 API/UI의 실제 브라우저에서2개80EP 구매·각각 배치·두 번째만 드래그·회수·저장·새로고침 후 잔여1개를 확인했다. 이번 변경의 원격 DB/운영 배포/토스 실기기 검증은 하지 않았다.

아래는 기존 자유 배치 구현 기록이다. 동일 itemId1개 제한과 중복 검사 설명은 위 수량/instanceId 정책으로 대체한다.


2026-11-09 사용자 요청으로 고정 위치 정책을 교체했다. PDF의 정원 외형은 유지하며 편집 동작은 이 문서를 우선한다.

- 보유 아이템을 누르면 정원에 추가한다. 이미 배치한 보유품을 누르면 해당 아이템을 선택한다.
- 정원 안의 아이템을 직접 드래그해 옮긴다. pointer capture로 손가락/마우스가 아이템 밖으로 나가도 이동을 이어간다. 터치 중에는 아이템 영역에서 페이지 스크롤을 막는다.
- 선택 테두리와 배치 해제를 제공한다. 화면의 방향 버튼은 삭제했으며 키보드 방향키 접근성은 유지한다.
- 이동은 draft다. 저장해야 서버에 확정되며 취소/저장하지 않고 나가기는 이전 배치로 돌아간다. 기존 뒤로가기 루프 방지 동작을 유지한다.
- 정원 안에 아이템 전체가 들어오도록 경계를 제한한다. 겹침은 허용하고 아래쪽 아이템을 앞에 그린다. 편집 중 선택한 아이템은 앞에 표시한다.
- 보유한 종류마다1개, 최대12개. 미보유/캐릭터를 장식으로 추가·중복·경계 초과·동시 수정 충돌은 서버에서 거부한다. 배치 해제는 소유권을 삭제하지 않는다.
- 캐릭터 선택은 기존 단일 캐릭터 팝업을 유지한다. 친구 정원은 동일한 좌표를 편집 버튼 없이 표시한다.

## 저장 형식

PUT /v1/garden:

```json
{"revision":0,"character":"seed","placements":[{"itemId":"plant","x":0.65,"y":0.75}]}
```

x/y는0..1 비율 좌표, 원점은 좌측 상단, 이미지 앵커는 하단 중앙이다. 아이템 크기는 클라이언트 입력을 신뢰하지 않고 공통 gardenItemSize를 사용한다. 화면 크기가 달라져도 상대 위치를 유지한다.

기존 slots는 읽을 때 초기 좌표로 변환하고 저장 시 placements와 빈 legacy slots로 확정한다. 새 API 입력은 placements를 사용하므로 클라이언트/API를 함께 갱신해야 한다. 기존 JSON 집계 테이블을 사용하며 이번 변경에 새 SQL migration은 없다.

## 코드·검증

- packages/contracts/src/garden.ts: 좌표·최대 개수·크기·경계·이전 배치 읽기
- apps/api/src/modules/domain.ts: 소유권·중복·경계·revision 검증과 저장
- apps/miniapp/src/features/garden/screens.tsx: 드래그·방향키·임시 편집·상점/친구 표시
- tools/qa/garden-free-placement.mjs: 드래그·저장·재접속·320/375/480px·해제·친구 읽기 전용

단위 테스트23개, 로컬 PostgreSQL 통합4개, 모바일 전체 흐름8개 그룹 및 자유 배치 전용 시나리오가 통과했다. 실제 DB 저장/충돌/이전 JSON 좌표 변환은 격리 localhost DB에서 검증했다. 원격 Supabase를 변경한 것은 아니다.

생성기와 앱 전체의 운영 준비 상태는 CONTENT_STUDIO_IMPLEMENTATION_PLAN.md를 따른다. 정원 기능의 실구현 완료를 전체 앱의 실서비스 검증 완료로 확대 해석하지 않는다.

## 수집함 내용 변화 대응 · 2026-11-09

- 고정100px 높이/고정 텍스트 행/말줄임/작은8px 상태 글꼴은 폐기했다.96px 폭의 카드는 최소116px에서 내용에 맞게 늘어난다.
- 이미지32px, 이름 최소28px, 수량 최소18px, 상태 최소14px의 독립 grid 행을 사용한다. 텍스트 행은 auto 확장하며 flex 축소나 절대 위치를 사용하지 않는다.
- 긴 한글/영문 이름·공백 없는 문자열·수량·상태 모두 줄바꿈하며 글꼴 확대/줄 간격 증가 시 높이를 확장한다. 이미지 크기/로딩과 무관하게 별도 그림 행을 확보한다. 상태가 없는 카드도 빈 상태 행을 유지한다. 실제 수량 계약은0~99개다.
- 이름11px·수량12px·상태10px, 배율 line-height를 사용한다. 긴 이름을 자르거나 다른 행과 겹쳐 표시하지 않는다. 전체 이름/남은 수량의 접근성 설명은 유지한다.
- 미보유 빈 목록 문구도 줄바꿈하고 가로 스크롤 내에 표시한다.320px의 좁은 화면에서는 카드를 줄여 찌그러뜨리지 않고 수집함을 가로로 스크롤한다.
- 사용자 요청으로 이번 수정의 브라우저 검증은 생략했다. 아래/위의 과거 브라우저 검증은 이전 배치에 대한 기록이며 이번 배치의 검증으로 간주하지 않는다.
