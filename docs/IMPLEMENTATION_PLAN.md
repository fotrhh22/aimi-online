# AIMI 전체 앱 구현 계획

작성: 2026-11-08. 목표는 DEVELOPMENT_SPEC.md의 전체 앱 구현과 앱인토스 실기기 인수 검증이다. 현재 완료 범위는 홈 미리보기·초기 문서이며 나머지는 아래 순서로 진행한다. 인프라 상세는 [INFRASTRUCTURE_PLAN.md](INFRASTRUCTURE_PLAN.md)를 따른다.

## 진행 원칙

API 키·Gemini $200 예산안·OpenRouter/AA Actions 수집·게임 GitHub 참조 선별은 [추가 실행 계획](API_AND_GAME_RESOURCES_PLAN.md)을 따른다. P0에 설정·예산/수집 계약, P3에 버전 검증한 게임 엔진, P5에 실제 Gemini 비용 제어, P6에 수집 workflow를 포함한다.

한 단계는 코드·검증·문서 갱신까지 끝나야 완료다. 로컬 mock, 실제 개발 DB, 토스 샌드박스, 운영을 구분한다. UX 수치·모델명은 운영 정책으로 확정하지 않는다. 기존 부모 프로젝트와 분리하고 기존 디자인·제품 범위를 유지한다.

P2의 화면 골격은 P1과 일부 독립적으로 개발 가능하되, 경제 기능을 mock 잔액으로 완성 처리하지 않는다. 첫 인수 목표는 P3이며 전체 앱 완료는 P8까지 필요하다. 일정은 P3의 실제 게임·토스 연동 검증 결과를 보고 산정한다.

## 개발 기본안과 미결정 항목

| 항목 | 우선 적용할 개발 방향 | 확정이 필요한 시점 |
|---|---|---|
| 인프라 | 사용자 확인한 Render My Workspace, 신규 AIMI 전용 Supabase | 외부 생성 전 리전·플랜·저장소 선택 |
| DB 접근 | 서버 SQL 트랜잭션, Storage 서버 SDK, 자체 세션 | P0/P1 역할·migration·접속 검증 |
| 게임 | 명세 제안대로 Phaser 기반 2D, 한 캐릭터 공유 | P3 입력·성능 검증, 에셋 라이선스 확인 |
| 예산·경제 | 최고 기록 집계·첫 성공 보상 제안을 버전 정책으로 구현 | P3 보상표·환산·상한·중단/자정 유예·상점 가격 조정 |
| 첫 과제 | 소수 키워드와 검수된 성공/실패 대표 이미지로 시작 | P3 승인 이미지와 결과 커버리지 확보 |
| AI | 텍스트 모델 환경변수·DB 작업·제한된 재시도 | P5 실제 모델·호출 한도·지출 상한·보존 기간 |
| 추천 | 버전별 근거와 자체 품질 정책, 데이터 부족 시 N/A | P6 AA 접근 범위·모델 매핑·최소 품질 정책 |
| 토스 | 토스 로그인·자체 친구·공식 미니앱 공유 | P1/P4/P8 실제 appName·분류·콘솔·서버 연동 |

일일 게임 5회·챌린지 5회, 자유 입력 없는 챌린지, 사전 검수 결과 이미지, EP 비현금성, 게임/정원 캐릭터 통일은 이미 확정한 규칙이다. 나머지 숫자는 개발 기본안과 운영 확정을 구분한다.

## 검증 범위

- 순수 로직: 조건/필수/충돌·모델 임계값 경계, 예산·EP 산식, 추천 결측·단위·동점 처리.
- 실제 PostgreSQL 통합: 멱등성 키/본문 충돌, 잔액·원장 일치, 동시 구매·보상·마지막 횟수, 시스템 오류 비소모, 자정 경계, 정원 revision.
- 외부 연동: 토스 코드 교환·세션 폐기, Gemini 구조 검증·지출 예약·재시작, 모델 스냅샷 발행·실패 복원.
- 모바일 E2E: 전체 주요 흐름, 터치·키보드·순서 변경·시트/팝업 초점, 일시정지·백그라운드 복귀, 실제 토스 공유/초대.

## 다음 착수 작업

P0에서 API와 공유 계약의 실행 가능한 기반을 만든다. DB migration 초안과 원자적 경제 처리부터 설계하고, 현재 홈의 메모리 EP를 서버 데이터 경계로 교체한다. 동시에 P1에 필요한 토스 콘솔 정보와 신규 Supabase 구성을 준비한다. 진행 결과는 [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)에 갱신한다.
