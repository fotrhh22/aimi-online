# Vercel 개인 코드 데모 — 운영 종료

2026-11-13 사용자 요청으로 종료. Render의 `/web-demo` 전체 경로는410 `WEB_DEMO_CLOSED`를 반환하며 세션 발급·기록 조회·Gemini 호출을 수행하지 않는다. Vercel API 프록시도 전달 기능을 제거했고 웹 빌드는 JavaScript/API 없는 종료 안내만 생성한다. 기존 DB 데모 기록과 토스용 인증·Gemini 기능은 유지한다. Vercel 프로젝트 삭제는 사용자가 수행한다. 아래는 이전 구현 기록이다.

## 사용자 흐름

1. 첫 접속 화면에서 ‘접속 코드 생성하기’를 누른다. 서버가 128비트 난수 코드를 발급한다.
2. 발급 코드를 복사해 접속 코드 입력란에 붙여넣고 ‘시작하기’를 누른다. 코드 발급만으로 자동 로그인하지 않는다.
3. 기존 사용자는 새 코드 발급 없이 기존 코드로 접속한다. 브라우저에 유효한 세션이 남아 있으면 바로 기존 계정을 연다.
4. 계정 관리에서 복구용 접속 코드 복사·다른 코드로 접속·현재 코드의 기록 초기화를 제공한다.

접속 코드는 비밀번호 역할이다. 소셜 8자리 친구 코드와 다르며 친구에게 공유하지 않는다. 코드를 잃으면 본인 확인을 통한 복구 기능은 없다. 같은 코드를 입력한 사람은 같은 계정에 접속한다. 이것은 토스 본인 인증 계정이 아닌 독립된 데모 계정이다.

## 기록과 권한

- 기존 `aimi.test_demo_stores`에 `personal-web:<SHA256>` 행을 코드마다 분리한다. 운영 users·ep_wallets·ep_ledger를 사용하지 않는다.
- 시작 EP는 코드마다125EP다. 게임·챌린지·정원·보유품·출석·팁·친구 관계는 코드별로 저장한다.
- DB에는 복구 코드 원문을 저장하지 않는다. 클라이언트에는 현재 코드와 서명된 guest 세션을 저장한다. 로그·공개 캡처에 코드를 남기지 않는다.
- 세션은 계정 해시+epoch를 HMAC 서명한다. 다른 계정 해시로 변경하거나 기존 공유 테스트 토큰을 개인 API에 사용하면 거절한다.
- 초기화는 해당 행의 epoch를 변경하고 그 코드의 기록만 재설정한다. 기존 세션은 무효화되며 같은 복구 코드로 새 세션을 발급할 수 있다.
- 모모는 각 계정 내부 예시 친구다. 개인 코드 사용자끼리는 각자의 소셜 친구 코드로 요청·수락·공개 정원 방문이 가능하다. 친구 승인·공개 설정·차단 규칙을 유지한다.
- 초기화는 자신의 친구 관계도 지운다. 다른 사용자의 기존 목록에 남은 이전 ID는 조회 결과에서 제외된다.

## Gemini 한도

개인 계정을 늘리거나 초기화해도 Gemini 전체 한도는 늘지 않는다. 기존 `shared-ui-test-v1`의 최근60분20회와 최초 시작 기준48시간 종료 시점을 그대로 사용한다. 개인 계정 status는 전체 AI 사용량임을 표시한다. 코드별 기록 초기화는 이 전역 사용량·종료 시점을 바꾸지 않는다.

## 구현과 배포

- `/web-demo/session`: `{create:true}`로 발급, `{code:...}`로 기존 계정 접속. 모르는 코드를 입력해 새 계정을 자동 생성하지 않는다.
- `/web-demo/*`: 개인 계정 API. 기존 `/demo/*` 토스 공유 테스트와 `/auth/toss` 운영 인증은 유지한다.
- 요청별 AsyncLocalStorage에 repository를 두고 동시 사용자 간 계정 선택을 공유하지 않는다. 다중 친구 변경은 대상 행을 정렬 잠금해 원자적으로 반영한다.
- Vercel 프록시는 명시적인 개인 데모 경로만 추가 허용한다. 임의 upstream·운영 인증 경로는 허용하지 않는다.
- 기존 테이블·서버 signing key·Gemini 환경변수를 재사용하므로 새 환경변수나 migration은 없다. Backend Render 배포와 Vercel frontend 배포가 모두 필요하다.
- 공식 구현 근거: [Node AsyncLocalStorage](https://nodejs.org/api/async_context.html), [Fastify request context](https://github.com/fastify/fastify-request-context).

## 검증

- DB 임시 계정2개: 독립 잔액, 동시 요청, 기존 코드 복구, 잘못된 코드/서명 거절, 친구 요청·수락·방문, 개인 초기화 격리, 이전 토큰 무효화, DB 코드 원문 비저장.
- `node --import tsx tools/qa/personal-web-flow.mjs`: 모바일 웹 발급→직접 입력→접속→새로고침→세션 삭제 후 코드 복구. 테스트 행만 정리한다.
