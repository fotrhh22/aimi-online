# AI·정원·개발 상태 피드백 반영

2026-11-09. 로컬 코드와 별도 테스트 포트에서 검증했다. 사용자가 실행한5180/8081 서버, Render와 Supabase는 변경하지 않았다. API 코드를 반영하려면 사용자 서버를 재시작해야 한다.

## 개발 서버 상태

개발 서버는 메모리 저장소와 프로세스별 세션 키를 기본으로 사용한다. 서버 재시작 시 EP·구매·보유품·게임·출석·AI 작업을 초기화하고 이전 로그인 토큰을 거부한다. 브라우저 새로고침만으로 일반 게임/정원 상태를 삭제하지는 않는다. 운영 PostgreSQL·EP 원장에는 적용하지 않는다.

이전 tmp/prototype/state.json은 기본 실행에서 읽지 않는다. 파일 보존이 필요한 특별한 로컬 검증만 AIMI_DEV_PERSIST_STATE=true를 명시한다. 이를 사용하지 않는 일반 npm run dev는 매 서버 시작마다 새 상태다.

## 프롬프트 개선

- 문장 전체에 밑줄을 긋고 팁 팝업을 띄우던 UI를 삭제했다. 결과는 복사·편집 가능한 평문이며 작성 팁은 아래 설명에 넣는다.
- 기본 개선안에 원문에 없는 세부 주제·기법·형식·수량을 넣지 않는 시스템 규칙을 강화했다. 확장안도 원래 질문의 답변이 아닌 AI에 전달할 요청문이며 새 조건은 따로 밝힌다.
- 요청문 형태, 숫자 보존·임의 숫자 추가, 과도한 기본 확장, 미공개 추가 조건을 검사한다. 의미 보존을 모든 입력에서 정형적으로 보장하는 것은 아니다.
- 실제 Gemini 합성 호출1건 확인: ‘공부 잘하는 법 알려줘’ → ‘공부를 더 잘할 수 있는 방법을 알려줘.’ 확장안은 [공부하는 과목]·[학습 목표]와 이유/실천 순서 설명을 제안하는 요청문이었다.
- 런타임 시스템 프롬프트는 apps/api/src/services/llm/prompts.ts의 OPTIMIZER_SYSTEM_PROMPT가 단일 원본이다.

## 추천 목록

- 데이터는461개였지만 UI가 추천3개를 전체 목록처럼 사용하던 문제를 수정했다. 전체461개를 검색·스크롤할 수 있고 추천 최대3개만 연하게 강조한다. 초기60개 이후 점진적으로 렌더링한다.
- 팝업을 제거하고 등급 상자 아래 인라인 패널로 바꿨다. 위/아래 스와이프 또는 손잡이 버튼으로 펼치고 접는다. 내부 목록은 세로 스크롤한다.
- 최초 추천 요청에는 진행 상태·스피너를 표시하고 중복 누름을 막는다. 오류 시 진행 상태를 끝낸다.
- Small/Medium/High 전환은 이미 받은 TaskProfile과 전체 snapshot을 공유 추천 패키지의 동일 코드로 계산한다. API·LLM 재호출이나 새 로딩 화면이 없다.
- 모든 모델에 비교 가능한 AA 지표가 있는 것은 아니다. 검증된 매핑만 추천 후보에 포함하며 미연결 모델도 전체 목록/상세에서 확인할 수 있다.

## AI 화면 수명

- 기존 optimizer.input/job, recommendation.result 복원을 제거했다. 새 문서 시작 시 AI sessionStorage를 정리한다.
- pagehide, BFCache pageshow, visibilitychange(hidden)에서 AI 방문을 종료하고 진행 중 결과가 새 화면에 늦게 붙지 않게 한다. 게임·정원·로그인은 이 이벤트로 초기화하지 않는다.
- 개선기→추천기로 직접 넘기는 문장은 한 번 읽은 후 즉시 지운다. 모델 상세를 위한 짧은 전달 데이터도 외부 이동 시 지운다.
- 방문 UUID로 서버 AI 작업 캐시를 구분한다. 새 방문의 동일 입력은 예전 결과를 복원하지 않는다. 같은 방문의 중복 요청 방지와 사용자별 일일 사용량 제한은 유지한다. 운영 사용 이력·일일 한도를 지우는 기능이 아니다.

## 정원 편집·내비게이션

- 정원의 ‘소셜 · 친구 만나기’ 상자만 삭제했다. 하단 소셜 탭은 유지한다.
- 아이템은4개 고정 위치의 상자로 표시한다. 위치 텍스트는 상자 안에 추가하지 않았다. 상자를 누르면 같은 위치의 보유품 선택 팝업이 열린다. 현재 장착품은 대체 목록에서 제외하며 장착하지 않기도 선택할 수 있다.
- 팝업 선택은 draft다. 정원 저장 때 서버에 확정한다. 다른 위치·미보유 아이템은 노출하지 않으며 서버 소유권/위치 검증도 유지한다.
- 현재 PDF 예시 상품은 위치별1개다. 같은 위치의 다른 보유품이 없으면 안내 문구를 표시한다. 복수 후보 UI는 브라우저 전용2개 후보 fixture로 검증했다. 실제 상품·운영 보유품을 임의로 추가하지 않았다.
- 저장·닫기·확인 후 나가기에는 history.replaceState를 사용하여 종료된 편집 entry를 남기지 않는다. 정원/미션/소셜의 상단 뒤로가기는 홈으로 이동해 이전 편집 기록을 다시 열지 않는다. 편집 중 뒤로가기는 미저장 확인을 유지한다.

- 타입 검사·전체 빌드·단위 테스트21개, 모바일 기존 기능 흐름8개 그룹 통과.
