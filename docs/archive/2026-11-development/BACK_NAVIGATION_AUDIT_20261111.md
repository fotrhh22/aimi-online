# 화면 전개·뒤로가기 전수 조사

기준: 2026-11-11, 현재 로컬 코드. 원격 배포 상태와 구분한다.

후속 반영 완료: 현재 적용 정책은 BACK_NAVIGATION_POLICY.md를 따른다. 아래57개 결과는 수정 전 진단이며, 수정 후72개 경로 결과는 output/qa/BACK_NAVIGATION_APPLIED_20261111.json에 별도 보존한다.

## 조사 방식과 결과

- 실제 `app/context.tsx`의 `back()`·`popstate` 처리 함수를 변환해 메모리 History/DOM 어댑터에서 실행했다. 구현을 다시 흉내 낸 예상 함수가 아니라 현재 함수를 실행했다.
- 57개 경로: 권장 목적지와 일치40, 특별 처리 필요17. 같은 문제를 화면 버튼/SDK callback/브라우저 방식으로 반복한 건수를 포함한다. 독립 버그17개라는 의미가 아니다.
- 경로가 / → 상세로 바로 들어오는 경우, 정원 편집이 상점에서 열린 경우, 중첩 팝업, 앞으로가기까지 포함했다. 일반 진입에서는 정상이어도 다른 진입에서 실패하는 경우를 구분해야 한다.
- 테스트 어댑터의 guard와 팝업은 최소한의 상태 모형이다. 게임 물리·실제 저장·실제 React DOM·토스 기기의 제스처/키보드/네이티브 닫기를 실행한 것은 아니다. 기능 내부는 소스 분기 대조로 조사했다.
- 계정·DB·재화·게임 횟수·AI API를 변경하지 않았다. 앱 변경은 별도 요청한 정답 페이지의 모델 정보 버튼 조건 변경만 포함한다.

재현: `node tools/qa/back-navigation-audit.mjs`

| 공통 팝업 | 단일 / 중첩 / 저장 대기 / 지연 도착 | 키보드 → 최상위 popup → 편집/진행 guard → page 목적지 순 | 현재 화면/SDK는 첫 dialog 취소. 브라우저 pop은 이 단계가 없음 |
| 공통 키보드 | 입력 focus / 키보드 열림 / 스크롤 | 기기의 키보드 닫기와 페이지 이동을 중복 실행하지 않기 | 현재 JS에는 keyboard 우선 처리 없음. 실제 토스 기기에서 검증 필요 |
| 공통 오류·직접 진입 | 잘못된 URL / 인증 만료 / 없는 모델·친구·결과 | 의미 있는 목록/홈 fallback | 일부 화면만 fallback 버튼을 제공. 공통 back은 history 길이·앱 origin 확인 없음 |

## 실제 재현한 핵심 불일치

1. **화면/SDK와 브라우저 pop의 규칙이 다름.** `back()`에는 팝업과 challengeBackTarget이 있지만 `popstate`에는 같은 공통 처리가 없다. 팝업을 닫는 대신 페이지를 떠나는 시나리오를 재현했다.
2. **결과의 앞으로가기도 미션으로 바뀜.** 결과→정답으로 앞으로가기 했는데 결과 popstate 특례가 무조건 미션으로 보냈다. 뒤로/앞으로/복원을 구분해야 한다.
3. **직접 진입한 상세의 fallback 없음.** 모델 상세에 history entry 하나로 진입하면 `<`가 제자리였다. 친구 정원·상점·clean 편집도 진입 방식에 따라 목적지가 달라졌다.
4. **정원 clean 편집의 목적지가 고정되지 않음.** 정원→상점→편집에서 `<`는 정원이 아니라 상점으로 돌아갔다.
5. **중첩 팝업은 첫 dialog를 닫음.** 최상위 대신 아래 팝업을 선택하는 결과를 재현했다. 최상위 계층 관리가 필요하다.

아래는 소스로 확인한 별도 위험이며, 메모리 back handler만으로 실제 비동기 완료까지 재현했다고 주장하지 않는다.

6. **추천 상세 왕복의 상태 소실.** 추천에서 모델 상세로 이동하면 추천 component가 unmount된다. 복귀 시 Small/text 초기 상태이며 직접 입력·분석 결과·검색·스크롤이 소실될 수 있다. 사용자가 원한 실제 앱 이탈 시 초기화와 내부 이동을 구분해야 한다.
7. **변경/요청 진행 중 이탈 처리가 제각각.** 게임 저장·정원 저장·구매·친구 추가·계정 삭제는 동일 busy 정책이 없다. 공통 busy는 버튼 표시일 뿐 탐색 잠금이 아니다.
8. **챌린지 제출의 늦은 응답.** 다른 화면으로 나간 뒤 이전 컴포넌트의 submit 완료 callback이 결과 경로로 navigate할 수 있다.
9. **준비 팝업에서도 이미 게임1회 사용.** 실패·취소 문제가 아니라 횟수 차감 시점 정책이다. 현재 서버 기준을 UI 안내와 맞춰야 한다.
10. **날짜·세션 전환 중 과거 화면.** 새 content와 이전 result가 혼합되지 않도록 결과별 콘텐츠 버전 조회·확정된 종료 동선이 필요하다.

## 구현 우선순위 제안

### 1. 이동 정책 통합

페이지별 backTarget, 진입 origin, 화면 내부 단계, popup stack, 저장/요청 진행 상태를 한곳에서 결정한다. 개발 버튼·토스 callback·브라우저 pop을 같은 결정을 따르게 하되 History의 이동 방향은 보존한다. 전역에 개별 if를 계속 덧붙이지 않는다.

- 홈/미션/정원/소셜: 홈 또는 앱 나가기.
- 게임 진행: 일시정지 확인. 게임 결과: 홈.
- 챌린지 결과: 미션. 정답: 해당 결과. 조합: 선택. 선택: 미션.
- 정원 편집: 정원, 단 dirty면 저장 확인.
- 상점: 정원. 친구 정원: 소셜.
- 모델 상세: 진입한 추천/정답/결과 화면, 직접 진입이면 올바른 추천 분야.

### 2. 내부 왕복 상태 보존

챌린지 draft, 정원 draft, 개선 결과, 추천 출력 종류·모델군·검색·목록 위치를 앱 내부 왕복 동안 보존한다. 실제 앱 이탈 때 AI state를 초기화하려던 기존 사용자 정책은 유지하되 외부 링크·기기 복귀 기준을 명확히 정한다.

### 3. 진행 중 작업과 복구

구매·저장·탈퇴 같은 요청은 중복 호출과 늦은 UI 이동을 막는다. 서버 성공 결과는 재조회 가능해야 한다. ‘이탈 차단’과 ‘서버 요청 취소’를 같은 의미로 표현하지 않는다. 게임 시작 시점 차감 안내를 맞춘다.

### 4. 경계 인수

각 실제 모바일 플랫폼에서 키보드·토스 상단 `<`·하드웨어/제스처 back·close·백그라운드·네트워크 끊김·자정·연타를 확인한다. 현재 보고서는 이 실기기 인수의 완료를 의미하지 않는다.
