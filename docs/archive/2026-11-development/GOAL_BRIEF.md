# 전체 앱 구현 목표 입력안

다음 내용은 /goal에 사용할 준비 문서이며 자동으로 goal을 생성/활성화하지 않는다.

AIMI UX PDF v18(13슬라이드·35개 모바일 상태)와 최신 명세/정책에 따라 앱인토스 앱 전체를 구현하고 검증한다. 공통 토큰·UI·라우팅을 선행하고 기존 Supabase/API/경제/CI/Render 기반을 재사용한다. 인증·홈·미션·게임3종·챌린지·상점·정원·캐릭터·소셜·프롬프트 개선·모델 추천까지 실제 API와 연결한다. 만점 즉시 완주, 점수/예산/EP 상한, 만점 결과의 챌린지 단일 CTA를 적용한다. 추천은 LLM 업무/등급 분석+AA/OpenRouter 데이터의 코드 기반 최대3개다. 온라인 텍스트 모델은 gemini-3.1-flash-lite.

콘텐츠 생성기는 사용자가 추후 별도로 개발하므로 이번 목표에서 생성기 앱/이미지·키워드 생성 기능/별도 생성기 배포를 제외한다. 앱은 공유 Supabase의 승인 콘텐츠 계약·조회·일정 선택을 구현한다. 상점은 PDF 예시 에셋을 재사용하고 신규 AI 상품 제작은 요구하지 않는다. 대표 에셋·챌린지 샘플은 Codex가 PDF를 참고해 직접 준비한다. 목표 이미지·키워드·조건/비용·저/고 모델 정책·사전 제작 결과 이미지 매핑을 한 묶음으로 만들고 검증한다. 사용자의 샘플 제공이나 별도 생성기 완료를 선행 조건으로 두지 않는다. 개발용 fixture와 검수/발행 콘텐츠는 구분한다.

이미지 챌린지 제출 판정은 LLM이 아니라 서버 규칙 코드로 수행한다. 조건 ID 매칭·가중치/감점·필수/충돌 조건·모델 임계값을 버전 고정한다. 문장은 검수 템플릿으로 조합하고 결과 이미지는 profile+등급으로 조회한다. LLM 채점·실시간 이미지 생성·임베딩 기반 점수 변환을 넣지 않는다.

IMPLEMENTATION_PLAN.md 순서로 코드·검증·상태 문서를 갱신한다. 거래/판정/상한/중복/동시성/자정/복귀/미매칭을 적절히 검증한다. 토스 실기기·콘솔 설정 등 사용자 환경이 필요한 인수 항목은 준비를 끝내고 구체적인 남은 조건을 보고한다. 확인 못한 실기기/출시 상태를 완료로 선언하지 않는다. 외부 생성/배포는 세션 승인 범위에 맞춰 진행한다.

최종 산출물/공식 UI·UX 인수는 TOSS_DELIVERY_AND_ACCEPTANCE.md를 따른다. .ait와 실제 API/DB를 제공하고 실기기·심사·출시 상태를 구분한다. Phase1에서 공식 TDS/SDK 호환성을 검증해 공통 UI에 적용한다. 모든 화면에서 SDK 닫기/시스템 뒤로가기의 이탈 경로를 보장한다.
