# 일별 학습 해설이 공통 팁으로 축소된 경로

2026-11-11. 이번 작업은 자료·코드·생성 요청 대조 조사다. 앱 코드·콘텐츠·팁 승인·정답·DB를 변경하지 않았다.

## 결론

사용자가 원한 것은 매일 사용한 모델, 실제 프롬프트의 구성 방식, 선택한 변수와 관계를 연결해 설명하는 개별 학습 해설이다. 현재는 서로 다른 문제와 프롬프트로 이미지를 만들었지만, 이 차이를 교육용 해설로 작성·연결하는 단계가 누락됐다.

‘모든 날에 공통 문구 하나만 보여준다’고 사용자와 합의한 정책을 찾은 것이 아니다. 현재 공통화는 제작 스크립트의 고정 템플릿과 최소한의 모델 팁 선택, 승인/활성화 누락, 앱 표시 필터가 겹쳐 발생했다.

## 실제 추적 결과

### 1. 최초7일 초안에는 일별 팁 연결이 있었다

output/aimi-content-reference-kit-7d/content/day-XX/manifest.private.json의 tips는 다음과 같다. 이 T번호는 일반 학습 팁20개의 ID이며 모델별 가이드14개의 별도 T번호와 같은 목록이 아니다.

| Day | 처음 연결된 일반 학습 팁 ID |
|---|---|
|01|T01, T05, T06, T09|
|02|T02, T03, T05, T10|
|03|T01, T02, T04, T19|
|04|T02, T03, T05, T07|
|05|T01, T03, T04, T20|
|06|T02, T03, T05, T10|
|07|T01, T02, T03, T05, T09|

정확한 수는 Day01~06 각4개, Day07은5개다. 따라서 처음부터 모든 날짜가 동일한 팁 한 개였던 것은 아니다. 일반 원리를 사용하더라도 일별로 선택·적용하는 구조는 이미 있었다.

### 2. 10일 묶음을 재작성할 때 기존 연결을 계승하지 않았다

aimi-content-studio/tools/author_batch.py:

- DATA에는 날짜별 제목·프롬프트 형식·문장·변수·대상·조건·오답 후보가 수작업 편집값으로 들어 있다.
- 229~232줄에서 `tips`를 매번 새 배열로 만들고, 모든 날에 같은 ‘단어를 장면과 연결하기’ 문구를 넣는다. 기존7일 manifest의 tips ID 연결을 읽어 계승하는 단계가 없다.
- 233줄에서 `next(...)`로 모델ID가 일치하는 첫 팁 하나만 고른다. 프롬프트 형식, 사용 변수, 작업 종류, 오늘의 장면과 맞는지 확인하지 않는다.
- 후보가 없으면 또 다른 일반 예시 문구를 추가한다. 현재 Day05가 해당한다.

즉, 원래의 일별 학습 포인트 선택은 여기서 사라졌고, 공통 팁+모델명 기준 첫 번째 팁 조합으로 대체됐다.

### 3. 모델ID만으로 선택해 맥락이 안 맞는 팁도 생겼다

- Day03/09의 GPT Image에는 T08 ‘무엇을 바꾸고 유지할지’가 선택됐다. 이 팁은 편집 상황을 설명하지만 실제 요청은 신규 이미지 생성이다. 같은 모델에 적용 가능한 T09 등도 있는데 `next`가 첫 항목만 선택했다.
- Day06 FLUX.2 Pro의 팁은 대상을 먼저 설명하라는 내용이지만 실제 작성 문장은 ‘표현 방식: 종이 콜라주’로 시작한다. 가이드와 실제 작성 형식의 연결을 검토한 해설이 없다.
- 단지 모델ID가 같다는 이유만으로 오늘의 프롬프트를 설명하는 팁이 완성되는 것은 아니다.

### 4. 생성 후에도 모델 팁 활성화·승인 연결이 끝나지 않았다

실제 모델과 생성 기록은 채워졌지만,10개 모두 model_tips_enabled=false, 모델 관련 팁9개는 editorial_draft로 남았다. 그 결과 모델별 텍스트는 저장돼 있어도 사용자에게는 보이지 않았다.

앱에는 관련 팁을 무조건 제외하는 추가 필터도 있었다. 이 필터는 이전 작업에서 enabled+승인+실제 모델 일치를 확인하는 방식으로 수정했지만, 그것만으로 오늘의 프롬프트·변수에 맞춘 해설이 새로 생기지는 않는다.

### 5. 생성 자체의 다양성은 실제로 유지됐다

10개 생성 request.body.prompt를 앱 authored_prompt와 대조한 결과10개 모두 동일했다. request.body.model과 actual_model_id도10개 모두 일치했다. 생성 단계에서 모두 같은 문장이나 모델로 바뀐 것은 아니다.

| Day | 실제 작성 형식 | 줄 수 | 조건 수 | 빠진 일별 해설의 예시 주제 |
|---|---|---:|---:|---|
|01|짧은 묘사 문단|1|8|대상·개수·배치를 한 문장에 연결. 시점의 실제 불일치는 별도 수정 필요|

위 마지막 열은 기존 작성 프롬프트에서 도출할 수 있는 해설 방향이지, 생성 이미지가 그 조건을 모두 충족했다는 검수 판정은 아니다. 특정 형식이 해당 모델에서 더 잘 작동한다고 비교 실험한 결과도 아니다.

### 6. 일별 해설을 요구하는 데이터·검증 계약도 없다

스키마에는 prompt_format(문자열), conditions, tips[]가 있지만 다음 내용이 필수 항목은 아니다.

- 왜 오늘 이 작성 형식을 사용했는지와 실제 문장 인용
- 오늘 사용한 변수·대상·관계의 해설
- 해당 모델/계열의 확인된 가이드를 이 문제에 어떻게 적용했는지
- 생성 결과에서 지켜진 조건과 어긋난 조건

검증기는 tips가 하나 이상이고 필드 형식이 맞으면 통과할 수 있다. 모든 날의 일반 팁 본문이 같은지, 개별 변수/문장을 인용하는지, 편집 팁을 생성 문제에 붙였는지 검사하지 않는다.

종료 API도 원문·정답·하이라이트·tips의 title/text를 반환할 뿐, 형식 선택 이유와 변수 해설을 반환하지 않는다. 프런트가 임의로 해설을 만들어 채울 문제가 아니라 제작 데이터가 먼저 완성돼야 한다.

## 사용자 의도에 맞는 복원 기준

1. **오늘의 작성 방식:** 실제 문장을 짧게 인용하고 왜 문단/서사/항목별 지시로 구성했는지 설명한다. 줄 수 자체를 모델의 필수 규칙으로 주장하지 않는다.
2. **오늘의 변수와 관계:** 이 문제의 대상·수량·색·재질·행동·상대 위치 중 핵심2~3개를 실제 표현과 연결한다. 날짜마다 장면이 다르므로 같은 원리라도 설명과 예시가 달라야 한다.
3. **사용 모델에 적용되는 가이드:** 확인된 모델/계열/작업 범위와 출처를 연결한다. 해당 문제에 쓴 방식과 연결되지 않는 편집 팁은 제외한다. Seedream처럼 모델 전용 근거가 없으면 실제 제작 예시 해설은 매일 다르게 작성하되 고유 규칙을 지어내지 않는다.
4. **생성 결과 확인:** 요청과 결과의 어긋남을 검수한다. Day01처럼 시점이 맞지 않으면 이를 모범 예시인 것처럼 설명하지 않는다.
5. 작성·검수·발행 검사에 일별 구체성, 변수/문장 인용, 모델+작업 적합성, 반복 문구 검사를 넣는다. 단어만 바꾼 억지 차별화나 검증하지 않은 우월성 설명은 제외한다.

이번 조사는 앱이나 콘텐츠를 다시 작성한 작업이 아니다.10일치 일별 해설의 재작성·승인·앱 연결은 별도 구현 단계로 남는다.
