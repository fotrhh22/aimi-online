# PDF 간격 규칙 전수 점검

2026-11-09. 로컬 구현 수정 및 Chrome 검사. 원격 배포·DB 변경 없음.

## 기준·범위

- output/pdf/AIMI_UX_Light.pdf의 12슬라이드 간격표와 화면별 제작 소스 spacing_layout.py, spacing_v16.py, fixed_garden.py, additional_screens.py를 대조했다. PDF 1·12페이지를 렌더링하여 화면과 육안 비교했다.
- 페이지 좌우24, 카드/팝업 내부16, 제목→설명8, 설명→목록12, 제목→첫 콘텐츠16, 동급 카드/버튼8, 묶음/본문→CTA24, 주 CTA 높이56·반경16을 적용한다. 기준은 글자 baseline이 아닌 line box다.
- tokens.css/styles.css/layout.css의 간격·글자 크기·행간·높이·반경 선언 492개를 목록화했다. JSX의 별도 inline 간격 경로도 검색했다. 게임/정원/썸네일 내부의 장면 좌표는 UI 여백 규칙과 구분한다.
- 정적 소스 전체 점검과 실제 동작 상태 검사를 구분한다. 모든 네트워크 실패 조합이나 PDF 35개 상태의 픽셀 단위 동일성을 검증했다는 뜻은 아니다.

폰트 파일은 PDF 원본을 유지한다. 글꼴 교체 없이 글자 크기·행간·보조색·주변 여백을 PDF 수치로 수정했다. design/tokens.json의 오래된 host-font 우선 안내도 실제 코드에 맞게 수정했다.

## 불가피한 차이·예외

- 홈 카드120px과 모든 지정 여백을 동시에 만족할 수 없다. 14+8+23+12+16+4+16+32=125px이므로5px 늘렸다. 보상 카드도60→64px로 늘렸다. 문구·글꼴·여백을 압축하지 않았다.
- 입력 데이터가 길면 카드와 팝업이 늘어나거나 스크롤된다. 내용이 긴 화면에서는 CTA를 본문 위로 끌어올리지 않는다. 짧은 화면에서 본문→하단 CTA는24px 이상의 남는 공간을 포함할 수 있다.
- 일반 화면 좌우는320/375/480 모두24px. 4열 보유품은 작은 화면에서 기존 반응형2열 예외를 유지한다. 터치 영역 확보로 PDF 정적 화면보다 길어지는 키워드 목록은 유지한다.
- 게임 결과의 공통 상단 위치·폭, 만점 단일 CTA는 유지한다. 네이티브 내비게이션·안전 영역·정원 장면의 내부 좌표는 일반 카드 간격과 다르다.
