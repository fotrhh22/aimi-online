# 이미지 챌린지 결과·해설 개선안

2026-11-11. 근거: CONTENT_TIP_AND_DAY01_AUDIT_20261111.md 및 DAILY_LEARNING_FEEDBACK_ROOT_CAUSE_20261111.md, 현재 UI/코드. UI 즉시 수정과 콘텐츠 검수 작업을 구분한다.

## 이번에 적용한 UI

1. 결과의 두 칸 배치를 한 줄 흐름으로 바꾼다. 이번 문장 아래에 일치율·맞은 키워드·다시 확인할 키워드를 이어서 표시한다. ‘키워드가 아예 포함 안 돼요’ 등 강한 총평은 제거한다. 원문/키워드/판정이 좌우에 흩어지지 않게 한다.
2. 첫 안내 팝업은 ‘그림을 설명하는 단어를 모두 골라 프롬프트를 맞춰보세요.’와 제출/힌트 비용 한 줄, 확인 버튼만 표시한다. 자세한 안내를 팝업에 중복 나열하지 않는다.
3. 조합 화면 상단에는 실제 다음 제출 순서인 N차 도전을 표시한다. ‘1차에서 확인한 조합’ 문구는 제거한다. 동일 키워드 집합이 기존 시도와 같으면 아래 이력을 펼쳐볼 수 있다고 안내하고 새 제출 대신 키워드 다시 고르기를 제공한다. 재조회는 예산을 사용하지 않는다.
4. 사용자 추가 답변에 따라 이전 도전 클릭은 별도 페이지 이동이 아니라 현재 화면의 details 펼침으로 처리한다. 이전 문장/키워드/일치율을 아래에 표시한다. 펼침/접힘은 현재 초안·예산·차수·URL·뒤로가기 이력을 바꾸지 않는다.
5. 실제 새 제출 결과의 뒤로가기 정책은 이번에 임의로 바꾸지 않았다. 과거 기록 조회 때문에 미션으로 나가게 되는 경로를 제거하는 것이 이번 수정 범위다. 현재 조합에서 뒤로가면 선택 화면으로 돌아가며 sessionStorage의 키워드를 유지한다.

## 성공·최종 실패 이후의 목표 구성 (후속 구현안)

### 결과 화면

- 성공: 성공 상태·목표 이미지·이번 선택과 일치율. 보상은 기존 서버의 pending→확인 후 지급 정책을 따른다.
- 최종 실패: 종료 상태·목표 이미지·이번 선택과 일치율. 더 제출할 수 있는 것처럼 안내하지 않는다.
- 종료되었으면 주요 버튼은 해설 보러가기 하나. 재도전 가능하면 다시 도전하기 하나.
- 과거 시도는 화면 안에서 접고 펼친다. 조회만으로 새 요청·과금·초안 덮어쓰기를 발생시키지 않는다.

### 해설 화면

1. 목표 이미지.
2. 검수된 정답 키워드.
3. 오늘의 장면 설명: 실제로 이미지에서 확인한 조건을 자연스러운 문장으로 연결한다.
4. 생성에 사용한 프롬프트: 실제 기록 원문을 별도로 표시한다. 장면 설명과 실제 생성 원문이 다르면 같은 문장이라고 주장하지 않는다.
5. 오늘의 작성 포인트: 오늘 사용한 대상/관계/구도/형식 중1~2개를 실제 프롬프트 구절과 연결해 설명한다. 모든 날에 같은 일반 팁을 넣지 않는다.
6. 이 모델에서 참고할 점: 실제 생성 모델·작업 방식에 맞고 출처 검토가 끝난 팁만 표시한다. 모델 전용 근거가 없으면 해당 영역을 숨기며 일반 원리를 모델 전용 규칙으로 포장하지 않는다.
7. 사용된 모델: 실제 모델명 + 굵은 자세히 알아보기 링크. 기존 모델 상세를 사용한다.
8. 홈으로 가기 주요 버튼. 해설에서 연 모델 상세의 뒤로가기는 기존 정책인 홈을 유지한다.

## 콘텐츠 검수를 UI보다 먼저 해결해야 하는 부분

- Day01의 내려다보기 조건은 현재 이미지에서 명확하지 않다. 생성 프롬프트에 적혔다는 이유만으로 필수 정답으로 유지하면 안 된다.
- 선택 A: 명확한 내려다보기 이미지로 재생성하고 전체 조건 검수. 선택 B: 현재 이미지를 유지하고 모호한 시점 조건을 제외/수정한 새 버전 제작. 실제 생성 원문은 어느 선택에서도 사후 변경하지 않는다.
- 정답 변경 시 정답ID·오답 후보·정답 개수 힌트·해설·강조 구절을 함께 갱신한다. 이미 시작한 시도는 기존 콘텐츠 버전으로 끝내야 한다.
-10일114개 조건은 기존 보고서 기준 검수 값이 미확정이다. 실제 보이는 조건을 확인한 뒤 신규 콘텐츠 버전의 채점 조건으로 확정한다.
- 모델 팁은 승인/활성화/실제 모델 일치뿐 아니라 신규 생성 vs 편집, 실제 사용한 문장 형식·변수까지 확인한다. Day03/09의 편집 팁 등 맥락이 다른 항목은 재선정한다.
- 비활성 초안 팁을 코드에서 모두 공개하거나 임의로 approved 처리하는 방식은 사용하지 않는다.

## 진행 순서

1. 이번 UI 수정 확인: 짧은 안내·세로 결과·인라인 이력·현재 초안 유지.
2. Day01 이미지/정답 처리 방식 결정 후10일 이미지 조건 검수.
3. 날짜별 장면 설명·작성 포인트·모델 참고 팁을 실제 생성 기록과 연결해 작성/승인.
4. 승인 데이터만 해설에 연결하고 성공/최종 실패에서 동일 정보 구조를 제공.
5. 날짜 전환·콘텐츠 버전·중복 제출/보상·뒤로가기·이력 접기/펼침을 검증.

이번 UI 작업은 콘텐츠 승인, 정답 변경, 이미지 재생성, 원격 DB/Render 반영을 포함하지 않는다. 미니앱 타입 검사·빌드로 검증했고 브라우저 시각 검증은 생략했다.
