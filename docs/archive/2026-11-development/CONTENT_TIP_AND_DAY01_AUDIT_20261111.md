# 모델별 팁·Day 01 시점 불일치 조사

2026-11-11 로컬 데이터와 실제 이미지 기준. 새 이미지 생성·유료 호출·원격 DB 변경은 수행하지 않았다.

## 결론

- 모델/계열 가이드가 없어졌거나 공통 팁으로 내용이 변환된 것이 아니다. 데이터9개 Day에 모델 관련 팁이 남아 있지만 모델 팁 비활성·편집 초안이며, 앱 필터도 이를 무조건 제외했다.
- Day01은 실제 이미지와 필수 시점 정답이 불일치/모호하다. 사과 측면이 크게 보이는 정면에 가까운 구도이며, ‘위에서 내려다본’을 분명한 시각 조건으로 맞히게 하기 어렵다.
- 생성 요청의 의도 조건을 이미지 검수 전에 그대로 정답 집합으로 쓰고 있는 것이 핵심이다. UI 문구나 팁 설명만의 문제가 아니다.

## 팁이 공통만 보인 경로

1. 참고자료 PROMPT_TIPS.md의14개는 출처와 적용 모델/계열이 연결된 편집 초안이다. 모든 내용을 모든 모델의 특수 규칙으로 일반화할 자료는 아니다. SOURCE_NOTES.md는 원문 확인 범위를 분리한다.
2. 콘텐츠 스튜디오 tools/author_batch.py가 모든 문제에 같은 일반 팁을 하나씩 추가하고, 모델별로 맞춘 팁1개를 별도로 넣었다. Seedream Day05는 명확한 모델별 작성법 근거가 부족해 예시 해설만 추가했다.
3. 실제 생성 후 actual_model_id와 generation_run_id는 채워졌지만 model_tips_enabled는10개 전부false, 모델 관련 팁9개는 approval=editorial_draft로 남았다.
4. 스튜디오 src/puzzle.py는 enabled+actual model match+approved일 때 표시하도록 작성돼 있었다. 앱 generated.ts는 이 세 조건을 검사하는 대신 requires_actual_model_match=true를 무조건 제외해, 이후 승인해도 모델 팁이 보이지 않는 추가 문제가 있었다.
5. 이번에는 앱 필터를 스튜디오와 같은 조건부 허용 규칙으로 수정했다. 승인값·활성화값은 임의로 바꾸지 않아 현재 콘텐츠의 실제 노출은 여전히 일반 팁이다.

## Day01 이미지 증거

- 실제 요청 body.model은 google/gemini-3.1-flash-image이고 prompt에는 ‘위에서 내려다본 장면’이 들어 있다. google-vertex/us만 허용하고 fallback은 꺼진 요청이다.
- 앱에 제공되는 원본 파일을 직접 열어 확인했다. 사과2개·붉은색·가로 나란히·흰색 배경·수채화는 관찰되지만, 시점은 정면에 가깝고 약간 위에서 본 정도로 보인다. 명확한 내려다보기/탑뷰로 출제하기에는 부적절하다.
- Day01 조건8개 모두 observed_value=null, review_status=unreviewed다. 팩도 published=false, review.status=unreviewed, scoring.release_ready=false다.
- 앱은 시점이 실제 보이는지 검사하지 않고 correct_keywords의ID 정확 일치로 채점한다. 따라서 실제 이미지와 다른 ‘의도된 정답’을 찾아야 하는 상황이 생긴다.
- 앱 이미지와 스튜디오의 실제 생성 원본은 크기·RGBA 픽셀이 완전히 같았다. 나머지9개도 파일 연결의 픽셀 동일성을 확인했다. PNG 재인코딩/포맷 변환으로 파일 해시만 다르므로, 현재 문제를 이미지 바꿔치기나 화면 crop으로 볼 근거는 없다.
- 전체10개 팩의114개 조건에 승인된 시각 검수 값이 없다. 나머지9개 이미지의 조건이 모두 틀렸다는 의미는 아니며, 이번 시각 판정은 Day01에 한정했다.

## 수정 선택지 — 이번에는 실행하지 않음

권장: Day01의 시점 요구를 유지하려면 명확한 위쪽 시점으로 이미지를 다시 만들고, 나머지7개 조건 및 오답 후보까지 사람이 확인한 뒤 새 콘텐츠 버전으로 발행한다. 실제 사용한 프롬프트·모델·제공자·이미지 해시를 다시 기록한다.

이미지를 유지하려면 시점 정답을 관찰 가능한 내용으로 수정하거나 모호한 조건을 제외한다. 이 경우 정답·오답 후보·개수 힌트·공개 설명·하이라이트가 함께 바뀌어야 한다. 실제 생성 요청 원문을 사후 수정해 원래 그 문장으로 생성한 것처럼 만들면 안 되므로, 생성 원문과 검수 후 장면 설명을 분리해야 한다.

어느 안이든 현재 진행 중인 시도에 정답을 몰래 바꾸지 않고 버전을 분리한다. 미검수 콘텐츠의 playable preview와 검수 승인 상태를 구분한다.

## 이번 UI 변경

정답 페이지에 ‘사용된 모델: [실제 카탈로그 모델명]’을 표시하고 굵은 ‘자세히 알아보기 ›’ 텍스트로 기존 모델 상세를 연다. 목록 조회가 실패하면 정확한 modelId로 표시하며 다른 모델명을 지어내지 않는다. 이 페이지에서 연 모델 상세의 뒤로가기는 기존 사용자 정책대로 홈이다.
