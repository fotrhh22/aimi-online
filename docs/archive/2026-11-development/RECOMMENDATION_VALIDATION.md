# 추천 적합성 검증 결과

2026-11-10. 분석 task-profile-v3, 모델 제품군 model-groups-v3, 실제 Gemini gemini-3.1-flash-lite를 사용했다. 프롬프트 예시와 다른 합성 고정문항18개를 사전에 정의하고 한 번씩 실행했다. 평가 데이터는 content/evals/recommendation-routing-v1.json이며 기준은 AIMI의 최소 적정 제품군 정책이다.

## 현재 자동 검증 범위

- 매 사용자 요청: TaskSchema의 enum·필드·길이·JSON 형식 검사. 허용하지 않은 등급/기능/모델명 필드가 나오면 AI_INVALID_OUTPUT으로 중단한다.
- 추천 코드: 검수된 AA 자료, 같은 지표 버전, 선택 제품군, 필수 기능, 최소 품질 기준, 컨텍스트/출력 길이, 유효한 가격/기준일을 확인한다. 적격 모델을 같은 입력2000/출력1000토큰 가정의 비용순으로 최대3개 반환한다.
- 매 요청마다 별도 AI가 의미적 적합성을 재심사하지는 않는다. 제품군 판단 자체의 타당성은 아래 고정 문항 평가와 사용자 피드백으로 검토한다.

- 전체18/18에서 등급·필수 기능·업무 유형·미확인 정보·추천 조건 검사를 통과했다. 전체 예측 분포는Small10/Medium4/High4다. 평가 문항 특성에 따른 분포이며 목표 비율을 강제하지 않는다.

## 별도 자동 테스트와 보완

1. 매우 싸도 품질 미달·필수 기능 누락·미검수·작은 컨텍스트·음수/NaN 가격·노후/잘못된 날짜를 가진 후보는 제외되는지 확인했다. 후보가 없다고 다른 등급으로 자동 전환하지 않는다.
2. 미래 날짜의 가격이 최신 자료로 통과하는 누락을 회귀 테스트로 발견했다. 현재 시점 이후 자료도 제외하도록 보완하고 recommendation-v4.1로 구분했다.
3. 최종 규칙으로 위18개의 저장된 실제 Gemini 분석을 오프라인 재검사해 모델 ID와 추천/보류 상태가 동일함을 확인했다. 이 재검사는 새로운 Gemini 호출이 아니다.
4. 잘못된 등급·미지원 기능 enum·지어낸 모델명 필드의 응답이 런타임에서 거절되는지 검증했다. 등급 전환 시 재호출·추가 한도 차감이 없는지도 기존 통합 검사를 유지한다.
5. 타입 검사·자동 테스트65개·전체 build 통과. 실제 공급자 호출은 이번 평가18건이며 형식만 확인하는 모의 응답으로 대체하지 않았다.

## 해석의 한계

18개 합성 문항 단일 시도의 정책 적합성 검사다. 전체 사용자 요청에 대한 정확도100%나 반복 안정성을 의미하지 않는다. 특히 추천된 개별 모델에 업무를 실제로 수행시켜 답변 품질을 측정한 시험은 아니다. AA 최소 점수와 제품군 기준도 AIMI 개발 정책이며 모든 업무 품질을 보장하지 않는다. 이미지/음성/영상 생성처럼 텍스트 추천 범위 밖의 출력 요구와 실제 문서 토큰량 추정은 별도 확장이 필요하다.

## 실행과 자료

일반 자동 검사는 npm test이며 실제 공급자 호출을 포함하지 않는다. 실제 Gemini 평가를 다시 실행하려면 npm run eval:recommendation을 사용한다. 설정된 서버 키로18건을 호출하므로 공급자 사용량을 쓴다. --ids=small-summary,boundary-json처럼 일부 문항만 선택할 수 있다. 연속 공급자/형식 실패3회면 중단하며 실패 결과를 통과로 바꾸지 않는다. 프롬프트·정책을 수정하면 새 데이터/버전과 함께 결과를 비교하고 실패 문항만 맞추는 식으로 정확도를 과장하지 않는다.

- 실제 결과: output/model-audit/recommendation-eval-latest.json
- 최종 필터 재검사: 해당 JSON의 qualityRecheck
- 원본 고정 평가 데이터: content/evals/recommendation-routing-v1.json
- 실행 도구: tools/eval-recommendation.mjs

브라우저 검증·원격DB 변경·Render 배포·Git push는 하지 않았다.
