# AIMI 전체 UX 구현 범위와 PDF 보강 검토

검토일: 2026-11-08. 기준: `design/reference/AIMI_UX_Light.pdf` 6페이지를 렌더링해 전체 확인. PDF 자체는 수정하지 않았다.

## 목표와 현재 위치

사용자 확정 목표는 PDF 전체 기능 구현이다. 로그인→홈 EP→첫 게임은 중간 검증 흐름이며 최종 납품 범위를 줄이는 기준이 아니다. 개선기·모델 추천/상세·게임 3종·이미지 챌린지·정원·두 상점·캐릭터·소셜과 실제 동작에 필요한 보조 상태까지 구현한다.

현재 완료는 API/DB 기반, 개발 경제 거래, CI와 Render 개발 배포다. UI는 홈 미리보기이고 토스 실인증·화면 API 연결·게임·AI 제품 기능은 아직 남았다. Gemini 모델 합성 호출 성공과 개선기 완성을 구분한다.

## 구현 단계와 산출물

1. **전체 화면·상태 계약 확정:** 기존 6페이지를 유지하고 미션·마이·로그인·보조 상태를 별도 화면/오버레이 목록으로 문서화. 모든 버튼의 목적지·취소·뒤로가기·복귀 동작 정의.
2. **공통 UI와 전체 라우팅:** TDS 적용·네이티브 내비게이션·탭·팝업·시트·상태 컴포넌트·API 클라이언트 구현. 전체 기능 경로를 먼저 열되 미구현을 작동하는 척하지 않음.
3. **토스 인증·홈·계정:** 실로그인·세션 복원·홈 EP·보상·미션/마이 연결. 실제 콘솔 appName·인증서·복호화·콜백 설정이 외부 선행 조건.
4. **게임 3종·챌린지 전체:** 공통 캐릭터/게임 상태·검증 계약을 만들고 길 건너기→다이노/3레인 러너를 순차 구현. 목표/키워드/결과 이미지·예산/횟수·자정/복구까지 완성.
5. **개선기 전체:** 확정 Gemini 모델로 개선/확장/팁·편집/복사·한도·작업 복구·추천 인계를 구현.
6. **모델 추천·데이터 운영:** AA/OpenRouter 스키마/권한·매핑·가격/지표·추천 정책·주간 수집 Actions·등급 시트/상세·결측 상태 완성. 현재 CI와 수집 workflow를 구분.
7. **정원·두 상점·캐릭터·소셜 전체:** 구매/보유·배치/저장·캐릭터 공통 적용·친구 요청/초대/방문/차단까지 완성.
8. **전체 앱 인수:** PDF의 모든 경로와 보강 상태를 실제 토스 실기기에서 검증. 게임 성능·키보드/접근성·네트워크 복구·계정 해제/탈퇴·운영 지출/데이터 백업까지 확인.

각 기능 묶음에서 UI/API/DB/콘텐츠/오류 복구/검증을 함께 끝낸다. 개발 순서를 나누더라도 최종 범위는 전체다.

## 구현 전 결정할 정책

- 게임 점수→예산 함수, EP 수집 상한, 첫 성공 보상·상품 가격, 중단/자정 유예.
- 챌린지 첫 과제·승인 결과 이미지 커버리지·조건 점수·모델 비용/임계값. 실제 AI 모델 벤치마크와 구분.
- 개선기/분석 각각의 일일 한도·무료 프로젝트 전체 한도·원문 보존 기간.
- 공개 모델 지표의 사용/재배포 권한·등급 정책·오래된 데이터 처리.
- 친구에게 공개할 정원/챌린지 상태, 미션·마이 최소 구성.

이 숫자와 정책은 PDF의 예시를 운영 확정값으로 복사하지 않는다. 개선기에 사용하는 `gemini-3.1-flash-lite`와 추천 화면에서 비교하는 여러 모델, 챌린지의 저/고성능 게임 등급은 각각 별개다.

## PDF 보강 산출물 제안

- 7페이지: 최초 이용·로그인·미션·마이.
- 8페이지: 공통 로딩/오류·한도·게임 중단/복구.
- 9페이지: 챌린지 예산·조건 피드백·제출 오류·결과 재진입.
- 10페이지: 개선기 편집·팁·한도와 추천의 근거 부족·결측.
- 11페이지: 상품 확인·구매·캐릭터 선택·정원 편집/저장.
- 12페이지: 친구 추가/수락·초대·방문·차단/비공개.

이는 검토 제안이며 페이지 추가·PDF 수정은 아직 하지 않았다. 기존 디자인 토큰·핵심 흐름을 유지하고, 추가 상태를 반드시 새 전체 화면으로 만들 필요는 없다.
