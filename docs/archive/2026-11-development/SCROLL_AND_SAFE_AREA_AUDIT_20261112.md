# 전체 화면 스크롤·상단 메뉴·보상 알림 점검

2026-11-12. 모바일 본문과 네이티브 메뉴 영역 분리, 불필요한 스크롤 제거, 긴 버튼 문구 전수 점검을 반영했다.

## 측정 조건과 구분

실제 웹 빌드/번들 폰트,393×852와320×740. 토스 상단 inset59+내비게이션48px/하단34px을 모사했다. 화면 상태는 합성 fixture이며 판정/보상/게임을 원격 실행하거나 초기화하지 않았다. 실제 iPhone/Toss의 대체 인수는 아니다. 스크롤 유무는 문구 길이·보유품·친구 수·선택 단어·기록 개수에 따라 변한다.

전수 대상은 앱의 모든 라우트다. 기본 상태23개를 두 폭에서 측정하고, 그 외 가변 상태는 코드와 공통 컨테이너 규칙으로 조사했다. 보고서의 ‘없음’은 측정한 대표 상태 기준이며 접근성 글자 확대/짧은 가로 화면/키보드/많은 콘텐츠에서 필요한 스크롤은 허용한다.

가로 스크롤은 별도다. 정원 보유품·모델 지원 비율은 기존 가로 이동을 유지하고,긴 모델 목록/입력창 스크롤도 제거하지 않았다.

## 원인과 수정

- 이전에는 document 전체가 스크롤돼 상단 padding까지 화면 밖으로 올라갔다. 이 때문에 내용이 투명한 토스 `<`/`×` 영역 아래로 들어갈 수 있었다.
- app-shell을 가시 뷰포트 높이로 제한하고,본체 main만 `overflow-y:auto`로 만든다. 제목·네이티브 안전 공간은 스크롤 밖에 둔다. 긴 내용을 잘라 숨기는 방식이 아니다.
- 뒤로가기/탭 이동 스크롤 저장·복원을 window 대신 활성 main 기준의 page-scroll.ts로 연결했다.
- 팝업도 상단 네이티브 영역과 하단 inset 안에 배치하도록 최대 높이·inset을 수정했다.
- 미션은 기능별 묶음으로 간격/이미지 높이/카드 패딩을 조정했다. 조합 확인은 이미지/키워드/문장/이전 내역의 중복 여백을 줄였다.
- 홈의 불필요한 간격과 정원 편집의 반복 드래그 설명을 정리했다. 정원 캔버스와 보유품 카드의 내용은 줄이거나 잘라 숨기지 않았다.
- 보상 완료는 ‘15 EP를 획득했어요.’처럼 실제 승인 금액을 표시하고 작은11px글씨·거의투명한배경·연한1px테두리로표시한다(사용자후속요구반영). 이전 텍스트 전용 toast 경로를 제거했다.
- 힌트 버튼은 ‘힌트 보기’,제목은 ‘정답 개수 힌트’.15예산 소모/구매 후 예산·남은 시도는 팝업 본문에서 확인 후 차감한다.

## 버튼 전수 조사

AST로 공통 Button54개(팝업 내부28개)를 확인했다. Button 안 br 없음,긴 팝업 버튼 문자열 없음. 팝업 제목도 조사했다. 남아 있던 긴 힌트 제목과 첫 안내 제목을 짧게 수정했다. 임의로 긴 본문까지 한 줄로 만들거나 생략하지 않는다.

검증 파일: tools/qa/audit-action-labels.mjs,tools/qa/scroll-audit.mjs,tools/qa/native-reward-toast.mjs,tools/qa/popup-mobile.mjs. 결과: output/qa/action-labels/audit.json 및 output/qa/scroll-audit/report.json.

보상15EP와 팝업 위치는 합성 서버 응답으로 검사했다. 실제 EP는 지급/변경하지 않았다. 테스트 전용 계정 관리에 UI 버전20261112-R3를 표시해 구 번들과 구분한다.
