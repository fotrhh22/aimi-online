# 추천 등급 분석·AA 성능 그래프 개선

2026-11-10. 기존156개 목록과 model-groups-v3를 유지한다.

## 추천 기준과 확인한 문제

모델군은 경량·효율형(Small), 균형형(Medium), 상위·전체 기능형(High)이다. Gemini는 사용자의 업무에 충분할 것으로 예상하는 최소 모델군을 제안한다. 실제 모델은 코드가 해당 제품군 안에서 필수 기능·검수된 품질·가격 기준으로 고른다. Medium으로 강제 fallback하는 로직은 없다.

기존 추천은 Gemini.optimize를 호출해 개선문·확장안·taskProfile을 함께 생성하고 개선문 검증까지 수행했다. 실제 합성 검사에서 단순 번역이 AI_NOT_A_PROMPT로 실패했으며, 조건 비교는Medium·분산 원장 설계는High로 통과했다. 따라서 모든 요청이Medium으로 분류되는 현상을 재현한 것은 아니지만, 추천과 무관한 개선문 검증이 단순 요청을 막는 구체적 문제를 확인했다.

## 변경

- Gemini.analyze를 추가해 TaskSchema만 요청·검증한다. 추천에서는 개선문을 만들지 않는다. 개선기에는 공통 TASK_ROUTING_RULES를 유지해 의미를 맞춘다.
- task-profile-v3로 캐시 해시를 구분한다. 분석 결과는 AIJob.taskAnalysis에 저장하며 JSON 상태 필드 추가이므로 새 SQL은 없다. 기존 optimizer result도 같은 버전/문장 해시이면 재사용할 수 있다.
- 단일 변환·요약·추출·간단 작성/작은 코드 수정은Small부터 검토한다. 독립 조건을 함께 만족하고 결과를 비교·통합해야 하면Medium, 많은 단계 의존·증명/불변식·복합 설계/장애 검증이면High를 검토한다.
- '분석/자세히/코드' 한 단어, 긴 입력, JSON/이미지 지원만으로 승격하지 않는다. 모호함은unknowns에 남긴다. 등급 비율을 맞추지 않는다.
- UI는 원래 업무 분석 제안 등급과 직접 선택한 비교 등급을 구분한다. 등급 전환으로 분석/한도 사용을 늘리지 않는다.
- 검수 AA10개·가격 가정입력2000/출력1000토큰·동일 제품군·일반 품질 gate5/12/20·최대3개 기준은 유지한다. Coding Index 제공 중단으로 코드 업무의 검증된 추천 근거 부족도 유지한다. 모델군 제안 성공과 실제 추천 후보 존재를 혼동하지 않는다.

## AA 그래프

종합·재무회계·전략운영·법률·보건의료·공학·경제7개를 한 줄의 세로 막대로 나란히 표시한다. 작은 화면에서는 차트 내부를 좌우 스크롤한다. 화면 전체에 가로 스크롤을 만들지 않도록 제한한다.

표시 축은고정0–100이다. 한 모델의 가장 높은 지표를100으로 만드는 자동 확대나 percentile 변환은 하지 않는다. 원점수를 숫자로 유지하고 시각적 막대만0–100범위로 제한한다. 표시 축을 모든 지표의 '정답률100%' 또는 최대치에 대한 품질 보장으로 설명하지 않는다. 범위 밖 점수도 실제 숫자는 유지한다.

동일 지표·버전·측정 설정의 모델끼리 비교해야 한다. 종합/분야별 지표는 평가 구성과 가중치가 달라 서로의 절대 우열로 단정하지 않는다. null은평가자료없음,0은실제0점이다. 2026-11-10 후속 변경: 전부null이면 AA 성능 상자 자체를 숨긴다. 측정 설정 선택 시 한 프로필 전체를 바꾸며 다른 설정의 점수는 섞지 않는다.

근거: [AA 종합 지표](https://artificialanalysis.ai/evaluations/artificial-analysis-intelligence-index), [분야별 지표 방법론](https://artificialanalysis.ai/methodology/capability-indices). 그래프의 고정 표시 눈금은 AIMI UI 규칙이다.
