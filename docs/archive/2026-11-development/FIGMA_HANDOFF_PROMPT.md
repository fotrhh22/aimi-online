# 개발 에이전트에게 전달할 질문

현재 /Users/hunhokang/Downloads/esg_campaign/aimi-online에서 개발 중인 AIMI에 대해, 앞으로 UI 구현 기준을 PDF보다 Figma로 전달하는 편이 너에게 더 편한지 검토해서 알려줘.

우선 현재 코드와 docs/current/IMPLEMENTATION_STATUS.md의 최신 기록을 확인해줘. 홈은 React/TypeScript 미리보기이며, 별도로 Fastify API·공유 Zod 계약·Supabase 계정/세션/EP 원장/출석·팁 거래 기반이 구현돼 있어. 반면 실제 토스 로그인과 홈 서버 연결, TDS 적용, 게임·챌린지·정원·AI 기능은 아직 후속 구현 대상이야. 오래된 상태 기록을 보고 이미 만든 API/DB를 미구현으로 판단하지 말고 실제 소스와 최신 기록을 대조해줘.

디자인 기준은 output/pdf/AIMI_UX_Light.pdf이며 현재 13슬라이드·35개 모바일 상태야. 8슬라이드 첫 번째·두 번째 화면의 ‘정원 꾸미러 가기 ›’는 삭제했고, 만점 달성·완주 팝업에는 ‘챌린지 도전하러 가기’만 있어. 정원은 고정 슬롯·캐릭터 한 명, 구매와 장착은 분리야.

Figma 전달본은 design/figma/AIMI_Figma_Importer.zip의 v19야. 실행하면 기존 편집을 덮어쓰지 않고 최신 35개 화면을 새 페이지로 생성해. 원격 Figma 파일에 자동 반영된 상태는 아니므로, 내가 가져온 뒤 전달하는 실제 파일/프레임 링크를 기준으로 봐줘. Figma MCP 한도가 남았는지, 실제 레이어/간격/스타일을 읽을 수 있는지도 확인해줘.

이 상태에서 아래를 짧게 답해줘.

1. 남은 모바일 UI를 구현할 때 Figma 링크와 PDF 중 무엇이 더 유용한가? Figma MCP가 막힌 경우 대안도 포함해줘.
2. Figma의 편집 가능한 레이어·토큰·프레임 정보를 실제 코드에 얼마나 재사용할 수 있고, 수동 구현이 필요한 부분은 무엇인가?
3. 파일 전체 링크, 화면별 node-id, 컴포넌트/디자인 토큰 중 내가 추가로 무엇을 전달하면 되는가?
4. 현재 만든 코드·API·DB를 유지하면서 UI 기준만 Figma로 전환하려면 어떤 순서로 진행하는 게 좋은가?

이번에는 전달 방식 검토와 의견만 줘. 기존 코드를 재생성하거나 DB·배포를 변경하지 마. 기능·경제·판정·API 규칙은 docs/archive/2026-11-development/DEVELOPMENT_SPEC.md 및 최신 정책 문서가 기준이고, Figma는 화면·문구·레이아웃 기준이야. 현재 추천 명칭 Small/Medium/High 등 최신 문서와 PDF가 다른 부분은 차이로 기록해줘.
