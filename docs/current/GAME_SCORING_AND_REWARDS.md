# 게임 점수·완주·보상 정책 v1

갱신: 2026-11-08. 사용자 확정: 게임별 만점/보상 상한을 두고 만점 도달 시 완주 종료한다. 세 게임100점은 개발 기본안이며 최종 밸런스 확정값이 아니다. 거리/예산/EP 구체 수치는 버전 설정과 실기기 검증으로 정한다. 현재 구현은 아래 최신 버전을 우선한다.

## 최신 실행 규칙 v11 · 코인 수집·빠른 차선

코인4~7개/판, 실제 접촉1개당1EP·회최대7/일15. 점수 자동 지급은 폐기한다. 세 게임 모두 실제 코인과 획득 피드백을 표시한다. Dino는 높이, Temple Run은 레인/거리, 길 건너기는2차원 접촉을 확인한다. 새 일일 총상한34EP다. EP_ECONOMY_POLICY.md/README 참조.

길 건너기의 일부 차선 차량은1.55배 속도로 이동하고 주황 계열로 구분한다. 같은 차선 속도를 통일해 차량 추월/겹침을 방지한다. 통나무 속도는 유지한다. 기존v10 이하 replay와 화면의 차량 이동은 이전 버전을 따른다.

## 이전 실행 규칙 v10 · 확정 EP 경제 정책 (2026-11-09)

게임 물리/조작은v9와 같으며 보상만점수10점당1EP·회당10/일20으로 조정했다. 전체 수입은 출석3·팁1·게임20·챌린지15=최대39EP다. 챌린지는 성공10+절약 보너스최대5, 상품은 가격대별로 재설정했다. 기준은 EP_ECONOMY_POLICY.md/README와 공통economy.ts다.

이전v1~v9로 시작한 플레이는 이전 규칙으로 정산하며 전환 당일 기존 지급/지갑을 되돌리지 않는다.39 상한은 새 정책의 정상 일일 운영 기준이다. 새 게임의 한도 계산에는 같은 날짜의 기존 지급액도 반영한다.

## 이전 실행 규칙 v9 · 길 건너기 입력 반응 (2026-11-09)

한 칸5tick(약167ms), 첫 입력 틱부터 이동 보간을 시작한다. 첫 이동이 끝나는 틱에 예약 방향을 받아 다음 이동을 시작하며, 틱별 이동량을 유지해 한 프레임에 두 칸을 순간이동하지 않는다. 두 연속 전진은 안전한 경로에서10tick 동안 일정하게 진행한다. 착지 즉시 연속 이동해도 도달 행의 점수를 보존하고 중간 차량 충돌은 생략하지 않는다.

키보드/모바일 방향 버튼 누르기는 이동이 끝날 때마다 일반 입력 이벤트를 기록한다. OS 키 반복 속도에 의존하지 않으며 release/pause/blur 등에 해제한다. 모바일 스와이프는18px를 넘은 시점에1회 입력, 일반 탭은 손을 뗄 때 전진한다. 이동 중에는 최신 예약 방향1개를 보존한다. 서버 replay는 동일한 틱·행동 로그를 사용한다.

새 플레이aimi-game-v9, 기존v1~v8 보존. Dino/Temple Run과 경제 상한은 v8과 같다. 자동 입력 테스트는 실제 모바일 터치 지연/재미 측정을 대체하지 않는다.

## 이전 실행 규칙 v8 · Dino 연속 점프 (2026-11-09)

Dino는 첫2개 적응 장애물 이후8행 패턴을 반복하며0/3/6번째 행 뒤에 약0.66~0.68초의 짧은 중심 간격을 둔다. 짧은 구간 이후에는1.04~1.14초 회복 구간과 넓은 장애물을 섞는다. 간격은 해당 장애물 위치의 예상 속도로 환산하며 v7의 추가 폭 가산 방식은 사용하지 않는다. 실제 도착 시각은 진행 중 가속과30Hz 양자화에 영향을 받는다.

한 번 점프해서 두 장애물을 통과할 수 없는 대표 조합을 검증했다. 두 번 탭하면 비행 중 두 번째 입력을 착지까지1회 예약한다. 공중에서 높이를 다시 올리는 이단 점프가 아니다. 꾹 누르기(화면/점프 버튼/Space/위쪽 방향키)는 착지 시 일반 jump 이벤트를 입력 로그에 남겨 연속 점프한다. 키보드 자동 반복 속도에 의존하지 않는다. 버튼에서는Enter도 지원한다. 손을 떼거나 키를 놓으면 반복 입력을 중단하고 pointer cancel/캡처 해제/창 blur/일시정지/화면 숨김/화면 이탈 시 누름 상태를 해제한다. 이미 별도로 두 번 탭해 예약한 점프는 다음 착지에 실행된다.

체공0.6초·정점70·속도300→680·완주28000·만점100·보상 상한은 유지한다. 새 세션aimi-game-v8, 이전v1~v7 replay는 보존한다. 자동 검증은 단일 점프의 두 번째 장애물 충돌, 두 번 탭/누름의1·19tick 연속 이륙, 추가 세 번째 점프 없음, 동일 이벤트 replay,30개 시드 완주를 포함한다. 브라우저 검증은 생략한다.

## 이전 실행 규칙 v7 · Dino 점프 리듬 (2026-11-09)

Dino의 체공 시간을24tick(0.8초)에서18tick(0.6초), 점프 정점84에서70으로 낮췄다. 속도는300+3.8×점수(최대680), 점프 입력 버퍼는5tick에서2tick으로 축소했다. 동일 점수에서 점프 중 이동하는 거리는 이전보다 짧으며 늦은 점프·너무 이른 점프의 허용 폭이 줄어든다.

장애물 생성 간격 계수는 초반1.12~1.20초, 이후0.78~1.12초로 줄였다. 실제 중심 간격은 생성 당시 속도×계수+max(32, 장애물 폭)이며 계수 자체가 실제 접촉 간격과 같지는 않다. 확대된 장애물 크기와28000 완주 거리는 유지한다. Temple Run과 길 건너기의 규칙은 v6와 같다.

대표54×48 장애물/50점 조건에서1/100초 간격으로 탐색한 성공 점프 시점 표본은46개에서27개로 줄었다. 이는 특정 조건의 시뮬레이션 검증이며 실기기 입력 지연이나 모든 패턴의 동일 허용 시간을 뜻하지 않는다.30개 시드의 자동 회피 완주와 replay 검증을 포함한다. 브라우저 플레이 검증은 사용자 요청으로 생략한다.

새 플레이는aimi-game-v7, 기존v1~v6의 초기화/점프/step/replay는 보존한다. API와 클라이언트를 함께 갱신하고 실행 중 API를 재시작해야 적용된다. 점수100·EP18/회60/일·예산150 상한은 유지한다.

## 이전 실행 규칙 v6 · 2026-11-09

사용자 피드백에 따라 Dino/Temple Run의 완주 거리를 v5 대비2배로 늘렸다. Dino는280거리/점, 총28000거리, 속도270+3.3×점수(최대600)다. Temple Run은20거리/점, 총2000거리, 속도22+0.4×점수(최대62)다. 둘의 월드 단위는 다르다. 예상 무중단 완주 시간은 각각 약68초/52초이며 시뮬레이션으로 확인한다. 보상 상한을 늘린 것이 아니다.

Dino 장애물은 초반24×34, 이후 폭26~54·높이36~52로 확대했다. 점프 높이84·체공24tick와 생성 간격을 유지하며 자동 입력 경계 테스트에서 통과 가능한 경로를 확인한다. 실제 손 조작의 재미를 자동 완주 결과로 대체하지 않는다. Temple Run의 양쪽 이동을 강제하는3종 패턴/차단 레인·안전 경로는 유지한다. 길 건너기 거리/난이도는 이번 변경에서 유지한다.

v1~v5의 초기화·step·replay를 보존한다. 이미 시작한 기록에는 그 버전을 사용하며 새 플레이만 aimi-game-v6를 발급한다. API와 클라이언트를 함께 반영해야 한다. 점수100·EP18/회60/일·예산 최대150은 그대로다.

## 점수

| 게임 | 득점 | 개발 기본 만점 |
|---|---|---|
| 길 건너기형 | 처음 도달한 전방 행1칸당 +1. 뒤로 이동/재방문은 가산 안 함 | 100칸=100점 |
| Dino형 | 시뮬레이션에서 전진한 거리의 구간마다 +1 | 완주 거리100구간=100점 |
| Temple Run형 | 코스 전진 거리의 구간마다 +1 | 완주 거리100구간=100점 |

러너 두 종류는 floor(distance/distancePerPoint). 점프/회피/좌우 이동 횟수·기기 렌더 프레임·벽시계 경과로 점수를 더하지 않는다. 일시정지 중 거리/점수/수집 없음. 점수는0..scoreCap, 완주 거리=distancePerPoint×scoreCap. 길 건너기는 maxReachedRow로 계산한다. 두 러너의 거리 단위·속도·장애물·도달 시간은 각각 조정하며 같은100점이 같은 난이도라는 뜻은 아니다. 게임 간 통합 점수 랭킹은 만들지 않는다.

## 만점 종료와 서버 확정

만점 도달 tick에서 simulation 종료(cleared). 그 뒤 입력/수집/장애물 진행 없음. 충돌(failed), 자발적 종료(abandoned), 만료(expired)와 상태를 구분한다. 같은 tick의 처리는 입력→이동→충돌 판정→안전한 전진/수집 확정→완주 판정 순으로 고정하고 서버 재생에도 동일하게 적용한다. 치명 충돌은 완주보다 우선하며 terminal tick까지 승인한 기록만 사용한다.

클라이언트는 완주 연출/서버 확인 상태를 거쳐 기존 게임 결과 팝업의 완주 variant를 표시한다. 서버는 play_id/seed/gameVersion과 입력 로그로 기록/완주를 검증한다. 초과 점수 제출을 무조건 만점으로 잘라 승인하지 않는다. 중복 완료는 기존 결과 반환, 응답 유실은 동일 ID 재조회. 이미 완료된 플레이를 이어 무한 수집할 수 없다. 만점 별도 EP 보너스는 자동 도입하지 않는다.

## 예산·EP 상한

scoreCap, distancePerPoint, maxPlayTicks, budgetMin, budgetCap, budgetCurve, epPerCollectible, epCapPerPlay, epCapPerDay, ruleVersion을 버전별 정책으로 둔다. 가격/보상 숫자가 없는 상태로 운영 발행하지 않는다.

- 예산 기준은 시작일의 승인된 일일 최고 기록. 5회 점수·예산을 누적 합산하지 않는다.
- earnedBudget = min(budgetCap, budgetCurve(bestScore)). 재도전은 최고 기록이 상승한 만큼의 예산 자격만 증가한다. 같은/낮은 점수 완료·페이지 재조회로 예산을 재충전하지 않는다.
- 챌린지의 비용이 제출별 한도인지 공유 잔액 차감인지 기존 UX/판정 계약에 명시해 분리한다. 제출 전 미리보기 계산을 실제 지출로 기록하지 않으며, 예산 자격 증가를 임의 반복 지급하지 않는다. 성공 EP 계산도 제출 시 확정한 예산/비용 snapshot을 사용한다.
- 수집 EP는 score와 별도. 이번 확정 EP=min(검증 수집 EP, 플레이 EP 상한, max(0, 일일 게임 EP 상한-이미 지급한 게임 EP)). 기존 경제 트랜잭션·원장·잠금으로 확정한다.
- 게임 수집 EP 일일 상한은 출석/팁/챌린지 성공과 구분한다. 각 보상에도 별도 중복/상한 규칙을 둔다. 친구·상점은 잔액 한도를 우회해 생성하지 않는다.
- 게임 최대5회/일, 챌린지 별도5회/일. 만점 후 남은 게임 횟수 사용은 가능하되 예산Cap/일일EP cap을 넘지 않는다. 중단/오류 회수와 자정 귀속은 game session 정책을 따른다.

## 이미지 수와 관계

고득점은 선택 가능 예산만 바꾸며 키워드 수/결과 이미지 수를 런타임에 늘리지 않는다. 날짜별 승인 challenge_version의 고정 조건/허용 조합/이미지 매핑 사용. 최대 예산에서 새롭게 가능한 조합까지 발행 전에 커버리지를 검증한다. 결과 미매칭은 시스템 오류로 복원하고 일반 오답으로 횟수/예산을 소모하지 않는다.

## 인수 조건

만점 직전/도달/초과, 재방문 칸, 점프·차선 변경 반복, 정지 후 재개, terminal tick 충돌, 중복 종료, 허위 점수, 최고 기록 갱신/미갱신, 마지막 일일EP 동시 지급, 상한 후 재시도, 만점 후 복귀, 자정/버전 전환, 최대 예산 조합 커버리지를 검사한다.
